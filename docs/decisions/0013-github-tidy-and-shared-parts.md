# 0013 — GitHub 식 정돈 · 서비스 부품 승격 · 판 갈라짐 바로잡기 (2026-10-24)

0009(밀도) · 0010(제목 위치) · 0012(덜어내기)는 그대로다. 이 결정은 **면을 가르는 법**을 바꾸고,
서비스들이 각자 만들던 부품 다섯을 정본으로 올리고, 서비스가 옛 판으로 태어나는 길을 막는다.

## 상황

사용자 지시(10-24): "모든 서비스 목록을 참고해서 UI/UX 를 어떻게 개선할지 · GitHub UI 가 괜찮은 듯 · GitHub UI/UX 와 claude.ai 디자인도 고려".
조사 넷(서브에이전트 — 서비스 18개 실측 · 세션 기록 속 사용자 말 1,076건 · Primer/claude.ai 공식 문서 · 부품 설계)과 Codex(gpt-6-astra, ultra) 교차 검토 두 번.

1. **판이 갈라져 있다.** 18개 중 정본 v3 를 그대로 쓰는 곳 6, **v1.2 사본에 머문 곳 12**. 원인은 새 서비스 틀(`_template`)이 v1.2 였고,
   배포 게이트 스윕이 동결된 v1.2 검사기를 불러 v1.2 사본을 "PASS" 로 남겼기 때문이다 — v3(09-05) 뒤에 만든 서비스 셋도 v1.2 로 태어났다.
2. **정본에 있는데 안 쓰고, 없으니 각자 만든다.** 파일 올리기 사용 0곳 · 토스트 0곳. 긴 작업 진행 4곳(단계 배지까지 치면 6곳) · 휴대폰 1인 링크 화면 4곳 · 서명 패드 3곳 ·
   한글/PDF 미리보기 6곳 · 좌우 두 칸 작업대 2곳이 제각각이다.
3. **사용자 말**(09-14~10-24): 정보 과다 26 · 위계/배치 19 · 입력 흐름 19 · 휴대폰 14 · 상태/진행 12 · 한글 문서 보기 10 · 일관성 10 · 시각 품질 9.
   v3.1 뒤 새로 드러난 것 — "한참 후에 보이다 보니까 깨진 듯한 느낌…프로그레스 바"(서명, 10-24) · "끝부분에서 계속 진행이 되지 않아서"(자막 추출, 10-23) ·
   "모바일에서…화면이 계속 흔들려 서명을 정상적으로 하기가 어렵네"(10-24, 10-01 에 고친 것이 재발) · "hwpx 문서에서 보여지는 것처럼 보여줘" ·
   "UIUX 도…동일하지도 않고…이질적인 느낌"(10-21).
4. **회색 바탕 위 흰 카드**(대비 1.13:1)가 화면마다 상자를 겹겹이 만든다. 카드 테두리(#E6EBF1)는 흰 위 1.20:1 로 거의 안 보여 경계가 바탕색 차이에만 기댔다.

## 결정

1. **면은 흰 바탕 + 테두리**(⚠ D1). 페이지 바탕 `#FFFFFF` · 테두리 `#D5DCE5`(= border-strong 값) · 셸 경계도 같은 선 · 모서리 6/4/12 ·
   주 버튼 색 그림자 없음(그림자는 모달·메뉴처럼 뜨는 층만) · 제목 굵기 600(페이지 제목 · 카드 제목 · 행 제목 · 모달 · 알림 · 토스트 · 빈 상태 · `.ggc-h1~3`).
   **새 색은 없다** — 바뀐 값은 전부 이미 토큰 파일에 있던 값이다. KPI 숫자 · LNB 현재 항목 · 배지 굵기는 그대로다.
   사용자가 질문 창에서 "바로 정본에 반영"을 골랐다(전 서비스 재복사 감수).
2. **상태 보이기 가이드**([guides/states.md](../guides/states.md)) — Primer UX 패턴(로딩 · 저장 · 폼 · 빈 화면 · 기능 저하 · 알림)을 우리 업무에 맞춰 **기본값**으로 둔다.
   토스트는 기본 알림 수단이 아니다(접근성 — 저절로 사라지고 시야 밖에 뜬다). 제출·결재 결과는 업무 근거라 화면에 남긴다.
3. **부품 다섯을 정본으로**(⚠ D1 — 컴포넌트 CSS 파일 끝에 덧붙임, 기존 선택자 무변경): `.ggc-job`(+`.ggc-progress`) · `.ggc-solo`(+`.ggc-modal--full`) · `.ggc-signature` ·
   `.ggc-viewer` · `.ggc-split`. 공통 분모만 — 흐름(서명 한 화면 · 설문 한 문항) · 렌더러(rhwp · pdf.js) · 내보내기(PNG)는 서비스 몫이다.
   Tier 2(React) 판은 다음 PR.
4. **레코드 처리 상태는 배지 하나**(0012 그대로). `.ggc-job` 은 시스템이 지금 이 화면에서 돌리는 작업에만 쓴다 — 단계 막대가 되살아나지 않게 문서 첫 표에 경계를 둔다.
5. **판이 갈라지지 않게** — 검사기 D1 이 사본의 판(머리말)과 정본 판을 함께 적는다 · `tools/sync-canon.py`(기본 미리보기)가 **공식 옛 판인 사본만** 정본으로 바꾼다(현지 수정본은 건드리지 않는다) ·
   새 서비스 틀의 사본을 v3.2 로 · 배포 게이트 스윕이 v3 정본의 검사기를 부른다. 검사기는 `.claude`(worktree 사본)를 건너뛰고 Next·Docusaurus 파비콘 관례를 안다.
6. **접근성 바로잡기 둘**(조사 중 발견): 체크박스·라디오 상자 테두리 1.38:1 → 비텍스트 전용 `--ggc-text-faint`(3.07:1, WCAG 1.4.11) ·
   유틸리티 바 「통합서비스」 라벨 4.02:1 → 6.04:1(이미 있던 링크 색).
