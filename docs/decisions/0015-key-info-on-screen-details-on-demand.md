# 0015 — 핵심만 화면에, 보조 정보는 한 번 눌러서 (2026-10-26)

0012(덜어내기)는 그대로다. 0012 는 **"언제 보이나"** 를 정했다. 이 결정은 덜어낸 정보를 **어디로 옮기나**를 정한다.
옮길 자리가 없으면 덜어내기가 "지우기"가 되거나, 다시 화면에 쌓인다.

## 상황

사용자 지시(10-26): "지금은 화면에 너무 상세한 정보가 나오게 디자인 가이드가 되어 있어. 화면에는 중요한 메뉴정보만 나오고 자세한 정보는 툴팁으로 변경하고 싶어.
그리고 메뉴가 많은경우는 사이드네비게이션으로 하고, 간단한 정보 표시는 오른쪽에 드로어로 표시한다던가 하면 좋겠고, 왼쪽에 사이드바는 숨김 표시등이 되어야 할듯 해."
Codex(gpt-6-astra, ultra)와 상의했고, frontend-design 스킬(Anthropic 공식 플러그인)의 절차를 갤러리에 적용했다.

찾은 것:

1. **0012 가 문제로 꼽은 문장이 문서 곳곳에 남아 있었다.** `table.md` 「식별자 · 소관 · 기간 · 담당 · 상태가 있어야 업무 표다」 · `stat.md` 「정확히 4개」 + 추세 줄 ·
   `page-head.md` 「h1 + 설명 한 줄 + 주 액션」 · `list-row.md` 「메타는 식별자 · 소관 · 날짜 · 담당 순」 · `work-layout.md` 「표의 모든 데이터 열」.
   서비스는 원칙(less.md)보다 **복사하는 예제와 부품 문서**를 따른다.
2. **갤러리 실화면이 그 문장대로 그렸다** — 대시보드 KPI 추세 줄 넷 · 카드 머리 부제 넷 · 행마다 「위원회 · 정책지원관 이○○ · 단계」 · 의안 목록 9열.
   실화면에 툴팁은 0건이었다.
3. **보조 정보를 옮길 자리가 Tier 1 에 없었다.** 툴팁은 "툴팁에만 있는 정보는 없는 정보"라 옮길 수 없고, 팝오버 · 정보 서랍이 없었다.
   서랍은 휴대폰 전체메뉴 전용이었다. Tier 2 에는 `sheet` · `popover` · `tooltip` 이 이미 있다.
4. **PC 왼쪽 메뉴는 아이콘 줄로 접히기만 했다.** 완전히 숨길 수 없었고, 쪽을 옮기면 접힘이 풀렸고, 접힌 아이콘의 이름은 브라우저 기본 `title` 로만 보였다.
5. **툴팁이 문서와 다르게 동작했다** — 문서는 "툴팁 위로 마우스를 옮겨도 닫히지 않는다"인데, `pointer-events:none` 과 8px 간격 때문에 닫혔다(WCAG 1.4.13 hoverable).

## 결정

1. **정보 배치표를 둔다.** 정보 종류마다 기본 자리를 정한다.

   | 어디에 | 무엇을 |
   |---|---|
   | 화면에 늘 | 화면 이름 · 대상 이름 · 현재 상태 · 지금 할 행동 · 결과 건수(한 곳) · 마감 일시 · 저장 상태 · 오류와 복구 방법 |
   | 툴팁 `.ggc-tooltip` | 아이콘 단추 이름 · 약어 풀이 · 잘린 값 전체 |
   | 토글팁 `.ggc-toggletip` (신설) | 집계 기준 · 용어 설명 · 전 회기 대비 같은 보충 숫자 |
   | 정보 서랍 `.ggc-modal--sheet` (신설) | 한 건의 담당 · 소관 · 접수/수정 시각 · 장소 · 이력 요약 |
   | 상세 화면 · `.ggc-split` | 긴 본문 · 전체 이력 · 편집 · 결재 판단 |

   **비교에 쓰는 항목은 화면에 남긴다** — 여러 행을 나란히 보는 목록의 소관 · 접수일, 배분 화면의 담당자.
   배치표는 기본값이다. 그 화면에서 그 정보로 무엇을 고르는지 말할 수 있으면 화면에 둔다(0012 결정 1 과 같은 판정).
2. **툴팁 규칙은 유지한다** — 판단 · 실행 · 복구에 필요한 정보를 툴팁에만 두지 않는다. 사용자의 "자세한 정보는 툴팁"은
   PC 마우스용 **툴팁**과 휴대폰 · 화면낭독기로도 열리는 **토글팁(ⓘ)** 둘로 나눠 받는다. 툴팁은 포인터를 옮겨도 닫히지 않게 고친다.
3. **토글팁은 네이티브 `<details>`** — 스크립트 없이 누르기 · Enter · Space 로 열린다(`.ggc-menu` 와 같은 방식). 폭 320, 링크 하나까지.
   ESC · 바깥 누르기 닫기와 가장자리 보정은 behaviors ⑥. `role="tooltip"` 을 쓰지 않는다(펼침 단추다).
4. **정보 서랍은 모달의 변형** `.ggc-modal--sheet` — 오른쪽에 붙고 높이는 화면 전체, 폭 400(`.ggc-split` 기본 폭과 같다), ≤900 은 화면 가득.
   `<dialog>` 라 초점 가두기 · ESC · 배경 클릭 · 초점 복귀를 behaviors ② 가 그대로 한다. 읽기 전용이다 — 편집 · 결재 확정은 넣지 않는다.
   휴대폰 「전체메뉴」 서랍(0014)과는 한 번에 하나만 열린다. 주소(URL) · 뒤로가기는 서비스가 정한다(sheet.md 에 지침).
5. **왼쪽 메뉴 완전 숨김** — `.ggc-lnb[data-ggc-lnb-collapse="hide"]` 이면 PC 단추(「메뉴 숨기기」/「메뉴 표시」)가 메뉴를 숨기고 본문이 넓어진다.
   속성이 없으면 지금처럼 아이콘 줄로 접는다(옛 마크업 그대로). 단추 하나 · 두 상태 — 펼침 → 아이콘 → 숨김 순환은 두지 않는다.
   **처음엔 펼친다.** 접힘 · 숨김은 서비스(첫 경로 조각, `data-ggc-lnb-key` 로 바꿈)마다 `localStorage` 에 기억한다. ≤900 은 늘 닫힌 전체메뉴로 시작한다.
   아이콘 줄의 이름은 디자인 툴팁(`.ggc-tooltip--float`)으로 보인다 — LNB 스크롤에 잘리지 않게 body 에 하나 둔다.
6. **숨길 수 있는 셸의 제목은 기본형(h1 보임)** — 0012 의 간결형 제목은 "펼친 왼쪽 메뉴의 현재 항목"이 조건이라, 메뉴를 숨기면 현재 위치가 사라진다.
7. **메뉴 개수 기준은 지금 규칙 그대로** — 화면(목적지) 5개 이하면 ⓐ 유틸리티 바만, 넘으면 ⓑ 풀셸(LNB). 2단까지, 3단은 만들지 않는다.
   Tier 2 sidebar 의 "1단 6개 · 그룹 3개를 넘으면 화면을 줄인다"는 **"넘으면 구조를 검토한다"** 로 고친다 — 기능을 지우라는 뜻으로 읽혔다.
8. **처방형 문장을 조건형으로** — 「정확히 4」「있어야 업무 표다」「설명 한 줄」「메타는 ○ 순」을 「그 정보로 무엇을 고르는지 말할 수 있을 때」로 바꾼다.
   `.meta` · `.sub` · `.trend` 를 CSS 로 한꺼번에 숨기지 않는다 — 예제에서 채우지 않는 방식으로 줄인다.
9. **새 토큰은 없다.** 폭은 `.ggc-split` 처럼 간격 토큰으로 잰다(400 = `--ggc-space-11` × 5 · 320 = × 4). 컴포넌트 CSS · 동작 JS 바이트는 바뀌므로 ⚠ D1 이다.
10. **기존 서비스는 일괄로 바꾸지 않는다**(0012-7) — 그 화면을 다음에 고칠 때 적용한다.

## frontend-design 스킬을 어디까지 적용했나

이 스킬은 "대담한 색 · 서체"를 권하지만 **의뢰(brief)의 말이 먼저**라고도 한다. 이 저장소의 의뢰는 새 주색 금지 · 다크모드 금지 · 외부 CDN 금지다.

| 가져온 것 | 적용 |
|---|---|
| 계획 → 의뢰와 대조 → 만들기 → 캡처 보고 고치기 | 쪽마다 "누가 무엇을 처리하나" 한 줄 → 「생성물 티」 목록 대조 → 캡처로 「하나 더 빼기」 |
| "구조는 정보다" — 테두리 · 번호 · 라벨은 내용을 말해야 한다 | 제목을 되풀이하는 부제 · 의미 없는 카드 쪼개기를 뺐다 |
| 「생성물 티」 목록 | `A · B · C` 가운뎃점 메타 줄 · 행동과 무관한 큰 숫자 + 보조 통계 KPI · 모든 제목 위 부제 — 갤러리에서 줄였다 |
| 글은 사용자 말로 · 단추는 결과를 말한다 | 「정보 보기」 · 「상세 화면 열기」 |
| 사람의 동작에 답하는 움직임만 | 정보 서랍이 열릴 때 한 번 밀려 들어온다(동작 줄이기 설정이면 없음) |

가져오지 않은 것: 새 팔레트 · 새 서체 · 다크모드 · 장식용 등장 효과 · 카드마다 다른 모서리.
