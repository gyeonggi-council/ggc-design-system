# 0014 — 휴대폰 메뉴는 오른쪽 · 모든 쪽이 같은 부품 규칙 (2026-10-25)

0013(흰 바탕 + 테두리 · 부품 다섯)은 그대로다. 이 결정은 **쪽마다 갈라져 있던 같은 부품의 모양을 정본 한 곳으로 모으고**,
업무 셸과 대민 셸의 휴대폰 메뉴 위치를 맞춘다. v3.2 는 아직 배포 전이라 같은 판에 넣는다.

## 상황

사용자 지시(10-25): "코덱스랑 상의해서 코덱스 서브에이전트들을 이용해서 디자인의 일관성 적용되게 해줘. 지금 페이지 뿐만이 아니라 모든 디자인 페이지에 동일하게 …
왼쪽에 CI마크가 있다면 오른쪽에 햄버거 마크가 있다던가, 모바일에서 봤을 때에는 아래쪽에 메뉴를 둔다든가 하는 게 낫지 않을까?"
그 직전 목업(실시간 자막 「다시보기」) 댓글 둘: "제목이 3줄로 나옴" · "확정은 오른쪽 정렬로. 회의록 보기 버튼은 밑에 … 제목도 좀 살짝 크게".

갤러리 18쪽 + 목업을 PC 1440 · 휴대폰 390 으로 찍어(41장) Codex(gpt-6-astra, ultra — 하위 에이전트 다섯: 메뉴 패턴 · 업무 13쪽 · 대민 5쪽 · 행·표 · 접근성)에 맡겼다. 찾은 것:

1. **휴대폰 메뉴 단추가 셸마다 반대다.** 업무 `[≡][CI][검색][알림]` + 왼쪽 서랍, 대민(KRDS) `[CI][검색][≡ 전체메뉴]` + 오른쪽 패널.
2. **같은 부품이 쪽마다 다른 모양이다.** 카드 모서리 16(기본) · 6(`.ggc-work` 쪽) — v3.2 의 6/4/12 는 토큰만 바뀌고 카드 16 · KPI 14 · 입력 10 · 작은 단추 8 은 리터럴이라 따라오지 않았다.
   카드 머리 여백 18/22 와 행 여백 12/16 이 달라 제목과 행의 왼쪽 끝이 어긋났다. 대시보드·의안 목록·위저드(`.ggc-work`)에만 카드·KPI·행·휴대폰 보정이 따로 있었다.
3. **레코드 행(상태 + 동작)이 세 모양이다** — 대시보드(상태·시각이 제목 아래 줄) · 의안 카드(단추 왼쪽 아래) · 목업(상태 위 · 단추 아래 · 오른쪽).
4. **표가 휴대폰에서 낱말 가운데서 끊긴다**(「기획재 / 정위원회」) — 한글 기본 줄바꿈이 음절 단위라 표 칸이 끝없이 좁아졌다.
5. **대민 사이드 메뉴가 휴대폰 첫 화면을 다 덮는다** · 대민 메인 검색칸이 휴대폰에서 납작해진다.

## 결정

1. **휴대폰(≤900) 머리는 CI 왼쪽 · 「전체메뉴」 오른쪽, 메뉴는 오른쪽 서랍** — 업무·대민이 같은 자리 · 같은 말 · 같은 폭(`min(360px, 88vw)`) · 같은 머리(「전체메뉴」 + 닫기).
   PC 의 LNB 접기는 왼쪽 그대로 두되 **단추를 나눈다**: `[data-ggc-lnb-toggle]`(PC · GNB 맨 앞) / `[data-ggc-drawer-toggle]`(≤900 · GNB 맨 끝).
   behaviors ③ 이 없으면 만들고, 옛 마크업이 맨 앞에 둔 서랍 단추는 맨 끝으로 옮긴다 — 서비스는 마크업을 고치지 않아도 된다. ≤600 에서 GNB 검색은 아이콘으로 접혔다가 누르면 펼쳐진다.
2. **바닥 탭바는 두지 않는다.** 서비스 메뉴는 4~12개 · 2단이라 3~5칸에 담기지 않고, 바닥은 이미 작업 띠(`.ggc-actionbar` · `.ggc-solo-bar` · `.ggc-work-actions`)가 쓴다.
   카카오톡 인앱 하단 도구막대 · iOS 홈 표시줄과도 겹친다. 오른쪽 메뉴가 누구에게나 엄지에 더 편하다고 단정하지도 않는다 — 고른 이유는 **두 셸이 같은 자리**라는 것이다.
3. **같은 부품은 한 모양** — 모서리는 토큰만(카드 · KPI · 위저드 `--ggc-radius-lg` · 입력 · 작은 단추 · 아이콘 상자 `--ggc-radius` · 태그 `--ggc-radius-sm`),
   카드 머리·바닥 여백 = 행 여백(`--ggc-row-pad`). `.ggc-work` 에만 있던 시각 규칙은 기본 부품으로 올리고 `.ggc-work` 에는 배치만 남긴다. 갤러리 바닥글·쪽 머리의 판 표기도 v3.2 하나로.
4. **목록 행** — 제목 `--ggc-text-md`(14 → 16) · 자르지 않고 줄바꿈. 오른쪽 칸에 단추가 있으면 **상태 위 · 단추 아래 · 오른쪽 끝**(사용자 확정), 휴대폰에서는 단추가 없어도 세로.
   의안 목록 카드도 같은 구조(`.ggc-work-record.ggc-list-row`). 표 안의 동작 칸에는 적용하지 않는다.
5. **한글은 낱말 단위로 줄을 바꾼다**(`word-break: keep-all; overflow-wrap: break-word` — 셸 뿌리에서 상속). 넓어진 표는 페이지가 아니라 `.ggc-table-wrap` 안에서 가로로 민다.
6. **대민 휴대폰 사이드 메뉴는 숨긴다**(KRDS side_navigation) — 그래서 사이드 메뉴의 **모든 목적지**가 전체메뉴에도 있어야 한다. 3단계(예: 의안 통계 → 회기별 · 위원회별 · 의원별)는 2단계 자리에 펼쳐 넣는다. 메인 검색칸은 높이를 지킨다.
7. **휴대폰 보정은 모두에게** — 페이지 머리 세로 쌓기 · 단추·페이지 이동 목표 40 · 입력 글자 16 이상(iOS 확대 방지) · KPI 두 칸(380 이하 한 칸) · 액션바 안전 영역 여백.
