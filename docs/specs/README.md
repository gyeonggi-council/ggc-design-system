# 제안(spec) — 결정 전의 기록

**권위: current(이 색인) · 안의 기록은 draft.** 구현을 지배하지 않는 제안은 여기 둔다. 작은 변경은 PR 본문으로 충분하다 — spec 은 **결과가 큰 변경**(토큰 바이트 변경 · 새 부품 · 새 패밀리 · 셸 규칙 · 검사기 규칙)에만 쓴다.

## 흐름

```
docs/specs/<주제>.md (draft, 틀: templates/knowledge/spec.md)
   → 검토 (PR 의도: record)
   → 채택: 결정 기록(ADR) 한 장 + 지배 기록(가이드 · 컴포넌트 · 계약)을 현재형으로 고친다 → spec 은 archived
   → 기각: spec 첫머리에 사유, archived
```

spec 이 채택된 뒤에도 current 로 남아 있으면 `check-knowledge.py` 가 WARN 을 낸다 — 지배 기록이 둘이 되는 것을 막는다.

## 큰 변경을 적을 때 꼭 있는 것

- **상황** — 어떤 서비스에서 누가 무엇을 겪었나(사용자 말 인용).
- **선택지** — 둘 이상. "하지 않는다"도 선택지다.
- **영향** — ⚠ D1(재복사) 여부 · 바뀌는 기록 · 검사기 변경.
- **검증** — 채택됐을 때 무엇을 재면 성공인가.
