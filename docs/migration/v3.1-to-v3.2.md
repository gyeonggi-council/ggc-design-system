# v3.1 → v3.2 — 흰 바탕 + 테두리, 서비스 부품 다섯 (그리고 v1.2 서비스가 건너오는 길)

⚠ **D1** — 정본 파일의 바이트가 바뀌었다: `ggc-tokens.css` · `ggc-components.css` · `ggc-behaviors.js`. 사본을 **재복사**한다.
`ggc-public.css` · `ggc-fonts.css` · `ggc-icons.svg` 는 그대로다. 결정: [ADR 0013](../decisions/0013-github-tidy-and-shared-parts.md).
**일괄로 옮기지 않는다** — 그 서비스의 화면을 다음에 고칠 때 옮기고, 옮긴 날 화면을 열어 확인한다(ADR 0012-7).

## 먼저 — 내 서비스의 사본이 어느 판인가

```bash
python design/check_design.py --report <서비스경로>     # D1 줄에 「사본 vX · 정본 v3.2」
python tools/sync-canon.py <서비스경로> --known <동결된 v1.2 정본 폴더>   # 미리보기 — 최신 / 공식 옛 판 / 현지 수정본
python tools/sync-canon.py <서비스경로> --known <…> --apply             # 공식 옛 판만 바꾼다 · 옛 사본은 ~/.cache/ggc-canon-backup/ 에
```

**현지 수정본**(어느 공식 판과도 다른 사본)은 도구가 건드리지 않는다. `diff` 로 차이를 보고 — 정본에 올릴 것이면 정본을 먼저 고치고,
아니면 서비스 자체 CSS 로 옮긴 뒤 다시 돌린다.

## 렌더가 어떻게 달라지나

| | v3.1 | v3.2 |
|---|---|---|
| 페이지 바탕 | `#EEF1F5` 회색 | `#FFFFFF` 흰색 — 면은 테두리로 가른다 |
| 카드·상자 테두리 · 셸 경계 | `#E6EBF1` · `#E2E7EE` | 둘 다 `#D5DCE5` |
| 모서리 버튼·입력 / 배지 / 카드 | 10 / 6 / 14 | 6 / 4 / 12 |
| 주 버튼 그림자 | 네이비 그림자 | 없음 |
| 제목 굵기(페이지 · 카드 · 행 · 모달 · 알림 · 토스트 · 빈 상태 · `.ggc-h1~3`) | 700~800 | 600 |
| 체크박스·라디오 상자 테두리 | `--ggc-border-strong`(흰 위 1.38:1) | `--ggc-text-faint`(3.07:1 — 조작 경계) |
| 좁은 화면(≤900) 액션바 저장 상태 | 숨김 | 한 줄 위로 접혀 보임 |
| 유틸리티 바 「통합서비스」 라벨 | 4.02:1 | 6.04:1 |

**리플로우는 없다**(치수·간격 그대로). 바뀌는 것은 면의 색·선·모서리·굵기다.
서비스 자체 CSS 가 `--ggc-bg` 위에 흰 카드를 얹어 구분하던 곳은 이제 테두리로만 구분된다 — 테두리 없는 흰 상자가 있으면 바탕에 묻힌다. 화면을 열어 확인한다.

## 새 부품 — 각자 만든 것을 바꿀 때

| 지금 서비스에 있는 것 | 정본 | 문서 |
|---|---|---|
| 진행 카드 · 단계 칩 · "처리 중" 띠 | `.ggc-job` · `.ggc-progress` | [job](../components/job.md) · [progress](../components/progress.md) |
| 로그인 없는 개인 링크 화면(설문 · 서명 · 신청 확인) | `.ggc-solo` · `.ggc-modal--full` | [solo](../components/solo.md) |
| 서명 패드 | `.ggc-signature` | [signature](../components/signature.md) |
| 한글·PDF 미리보기 | `.ggc-viewer` | [viewer](../components/viewer.md) |
| 좌우 분할 작업대 | `.ggc-split` | [split](../components/split.md) |

- **승인된 흐름은 그대로 둔다** — 서명 받는 분 화면의 「한 화면 + 바닥 3/6 작성」, 설문 의원 화면의 「한 화면 한 문항」, 주간보고 취합의 「왼쪽 400px 목록」은
  새 부품 위에서 같은 모양으로 옮긴다. 옮겼는데 사용자가 보던 모양이 바뀌면 옮기지 않는다.
- 레코드의 처리 단계 막대(접수 → 심사 → 가결)를 `.ggc-job` 으로 바꾸지 않는다 — 배지 하나다([states §8](../guides/states.md)).
- 동작이 필요한 부품(job · solo · signature · viewer · split)은 `ggc-behaviors.js` 를 함께 재복사해야 한다. `<script src="ggc-behaviors.js" defer>` 를 `<head>` 에 두면 두 칸 폭이 첫 화면부터 맞는다.

## v1.2 사본에 머문 서비스(12곳, 2026-10-24 실측)

v1.2 → v3.2 는 [v1.2-to-v2](v1.2-to-v2.md) → [v2-to-v3](v2-to-v3.md) → 이 문서 순서의 변경이 한꺼번에 온다(치수 · 제목 위치 · 아이콘 · 면).
한 번에 옮기되 **판정은 세 번** 한다 — 치수(첫 화면 행 수) · 제목(본문 첫 줄 h1) · 면(테두리). 주의:

- v1.2 플랫폼 판은 상단 통합서비스 띠(`.ggc-utility-bar`)를 기본 숨김으로 바꿔 두었다(2026-08-25). v3 정본은 띠를 보인다 — 옮기면 띠가 다시 나타난다. 그 서비스의 결정을 먼저 확인한다.
- 사용자가 서비스별로 확정한 배치(예: 자막 회의 목록은 카드 · 지식창고 큰 제목 없음 · 조례 공통 셸 보류)는 그대로 둔다.
