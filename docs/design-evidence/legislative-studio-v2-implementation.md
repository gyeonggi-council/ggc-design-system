# 의안 스튜디오 2.0 B안 디자인 적용 요청

- 작성일: 2026-09-19
- 상태: 사용자 검토를 거친 디자인 방향과 로컬 프로토타입. 실제 서비스 적용 완료를 의미하지 않음.
- 참고 시안: [ggc-legislative-studio-v2.html](./ggc-legislative-studio-v2.html)
- 대상 저장소: `gyeonggi-council/ggc-design-system`

## 목적

기존 B안의 차분한 문서 중심 디자인을 공통 디자인 시스템에 통합하고, 실제 서비스가 같은 기준으로 개편될 수 있도록 재사용 가능한 토큰·컴포넌트·화면 패턴과 적용 지침을 마련한다.

참고 HTML은 승인된 시각적 방향과 인터랙션 참고자료다. 정본 CSS, 생성 갤러리 또는 운영 서비스 코드를 이 파일로 통째로 대체하지 않는다. 이 자료 추가 PR과 실제 디자인 구현 PR은 구분한다.

## 시안을 확인하는 방법

파일을 내려받아 브라우저로 연다. 서버·패키지 설치·외부 요청 없이 동작한다. GitHub의 파일 보기에서는 HTML 소스만 표시된다.

- 첫 화면: 오늘의 의정 대시보드
- 좌측 메뉴: 업무용 16개 주요 메뉴와 세부 탭
- 상단 전환: 업무 스튜디오 / 도민 브리핑
- 참고 범위: 업무용 64개 화면·탭, 도민용 6개 화면, 합계 70개 렌더링 경로
- 운영 관리 > 메뉴·구현 범위: 의안관리 13개 대기능·42개 중기능 대응표

## 유지할 디자인 방향

1. 네이비 사이드바, 밝은 문서 배경, 절제된 녹색 강조와 충분한 여백.
2. 본문에 있는 명확한 페이지 제목·설명·주요 행동. 상단은 경로와 검색·알림 중심.
3. 대시보드의 다음 업무, 이어쓰기, 일정, 상태 분포를 연결하는 정보 위계.
4. 의안 문서 작업대의 처리 단계, 편집 지면, 진행 안내·AI 지원 패널 구성.
5. 목록·필터·상세·문서·처리 이력이 서로 이어지는 경험.
6. 업무용과 도민용의 목적을 구분한 공개 브리핑 디자인.
7. 모바일에서 전체 기능에 접근할 수 있는 메뉴·표·작업대·다이얼로그 구성.

## 구현 범위 1: 이 디자인 시스템 저장소

- 현재 계약, 프로필, 컴포넌트 인벤토리, 생성 도구, CI를 확인하고 기존 구조에 맞춰 구현한다.
- 색상·타이포·간격·형태를 `design/ggc-tokens.css` 정본 토큰에 매핑한다. 참고 HTML의 CSS 값을 페이지마다 복제하지 않는다.
- 새 값이 필요하면 중앙 토큰 또는 범위가 명확한 프로필로 정의한다. 기존 소비 서비스의 공통 색상·치수를 근거 없이 일괄 변경하지 않는다. 변경 이유와 영향, 시안과의 차이를 기록한다.
- 셸, 사이드바, 페이지 헤더, 카드, 표·필터, 상태 단계, 문서 작업대, 지원 패널, 다이얼로그, 모바일 메뉴를 공통 컴포넌트·패턴으로 구성한다.
- `design/ggc-components.css`, `design/ggc-public.css`, `design/ggc-behaviors.js` 등 실제 필요한 정본을 수정한다. 기존 컴포넌트·동작을 우선 재사용한다.
- `design/examples/dashboard.html`, `explore.html`, `wizard.html`, `public/index.html` 및 관련 갤러리에 승인된 방향을 반영한다. 추가 문서 작업대 예제가 필요하면 기존 갤러리 구조에 맞춰 추가한다.
- `design/components.tsv`, 관련 가이드·변경 이력·필요한 ADR을 실제 변경 범위에 맞춰 동기화한다.
- `DESIGN.md`, standalone HTML, 아이콘·스크린샷·레지스트리 등 생성물은 기존 생성 도구로 재생성한다. 생성물을 직접 고치거나 검사 규칙을 무력화해 통과시키지 않는다.

## 구현 범위 2: 실제 서비스 적용

이 저장소 밖의 서비스는 자동 변경되지 않는다. 실제 서비스 저장소·프레임워크·기존 메뉴를 확인한 뒤 별도 적용 PR과 마이그레이션 계획을 작성한다. 확인하지 않은 저장소를 추정하거나 가짜 운영 앱을 새로 만들지 않는다.

공통 매핑 대상:

| 메뉴 | 주요 화면·동작 |
| --- | --- |
| 오늘의 의정 | 대시보드, 다음 업무, 일정, 진행 분포 |
| 의안 스튜디오 | 내 의안, 문서 작업대, 버전·처리 이력 |
| 전자 연서 | 받은 요청, 보낸 요청, 진행 현황 |
| 접수·회부 관리 | 접수, 의장보고, 소관위 회부, 발의·철회 |
| 위원회 심사 | 심사, 입법예고, 심사보고서 |
| 본회의·후속 처리 | 본회의, 이송, 공포, 재의, 제소 |
| 의안 현황·조회 | 전체·계류·처리 의안, 청원 |
| 통합 문서함 | 개인·부서·공통·협업·결재, 즐겨찾기, 보존, 휴지통 |
| 통합 검색 | 의안·문서·회의와 결과 상세 연결 |
| 회의·일정 | 일정, 회의록, 회의자료 |
| 의정활동 지원 | 입법연구, 자료요구, 예산·비용추계, 감사, 홍보 |
| AI 의정 도우미 | 자료 Q&A, 작성, 회의, 예산, 민원, 미디어, 일정 |
| 현황 통계 | 기간·위원회 필터, 상태·발의자 집계 |
| 모바일·알림 | 알림함, 관심정보, 채널 설정, 모바일 접근 |
| 데이터 관리 | 카탈로그, 표준 사전, 품질 점검, 흐름 |
| 운영 관리 | 사용자·조직, 권한, 분류, 연계, 감사, 백업 |
| 도민 브리핑 | 브리핑, 공개 의안, 예고, 참여, 관심 의안, 공개 상세 |

메뉴별로 기존 경로, 대응 컴포넌트, API, 권한, 적용 여부, 미구현 사유를 표로 제출한다. 시안의 메뉴 수를 맞추기 위해 필요 없는 운영 메뉴를 추가하지 않는다. 기존 기능·데이터·API·인증·권한·라우팅은 보존한다.

## 운영에 복사하면 안 되는 시연 요소

- 모든 의안·인물·일정·수치·법정 절차 예시는 가상 데이터다.
- localStorage와 JSON 백업은 시연용이다. 운영 저장·보안 체계로 간주하지 않는다.
- 시연 정족수 3명, 가상 참여자 전환, 모의 연서는 법적 전자서명이나 본인인증이 아니다.
- 단계 변경·접수·결재·공개·알림은 로컬 시연이며 기관 시스템에 전송되지 않는다.
- AI는 API 연결 없이 규칙 기반 예시를 구성한다. 실제 생성형 AI·RAG·음성인식으로 표시하지 않는다.
- 역할·공개 상태·권한 토글은 인증 및 서버 측 접근통제를 대체하지 않는다.
- 파일 저장은 암호화 저장소가 아니다. 실제 민감자료를 넣지 않는다.
- 실제 연계가 없는 동작은 시연 표시를 유지하거나 비활성화한다. 작동하는 운영 기능처럼 꾸미지 않는다.
- 내부 자료와 공개 자료는 실제 서비스에서 서버 권한과 공개 검수 절차로 분리한다.

## 참고 시안에서 수행한 검증

다음은 참고 HTML의 로컬 검증 결과일 뿐, 이 저장소나 운영 서비스의 테스트 통과를 의미하지 않는다.

- 70개 화면·탭 렌더링과 노출 버튼의 처리 함수 매핑 확인
- 새 의안 작성·편집·저장·의안 간 본문 분리 확인
- 가상 연서 3명부터 발의·접수·보고·회부·심사·본회의·이송·공포까지 대표 흐름 확인
- 문서 등록·파일 등록·해시 기반 동일 파일 중복 방지 확인
- 로컬 검색·통계 필터·데이터 점검·백업 형식 검증 확인
- 390px 프레임에서 문서 작업대와 도민 화면의 전체 페이지 가로 넘침 없음 확인

## 공개 범위

공개 자료는 가상 데이터로 구성한 HTML과 이 적용 요청서뿐이다. 참고했던 ISP PPT 원본, 내부 업무자료, 개인 정보, 토큰·자격증명은 첨부하지 않는다.
