# v3.2.1 서비스 적용 — 음료 단체주문 `/drink` (2026-10-25)

정본 v3.2.1 을 **가동 중인 서비스 하나에 그날 바로 적용**하고, 사용자 반응을 받은 기록이다.
서비스는 업무플랫폼의 음료 단체주문(직원이 위원회별로 의원 음료 주문을 나눠 받고, 의원·외부 손님은 카톡 링크로 직접 고른다)이다.

## 사용자 피드백

> "디자인이 생각보다 잘 됐네." — 담당자, 2026-10-25 (텔레그램, 운영 배포 직후). 이어서 「그래도 만족스럽다」고 이 저장소에 피드백을 남겨 달라고 했다.

v3.2(ADR 0013 흰 바탕 + 테두리 · 부품 다섯)와 v3.2.1(통합서비스 띠 기본 숨김 · 1인 링크 셸 예외) 뒤 **첫 서비스 적용에 대한 긍정 반응**이다.
같은 서비스는 그날 아침 v3.0 사본(회색 바탕 · 연한 네이비 머리 띠 · 그림자 카드)으로 처음 공개됐다 — 바꾼 것은 화면 모양뿐이고 쓰는 순서는 같다.

## 사용자가 좋게 본 것으로 보이는 것 (추정 — 사용자는 항목을 짚지 않았다)

- 흰 바탕 + 테두리로 카드가 겹겹이 보이지 않는다 — 상태(받는 중 = 정보색 바탕 + 자물쇠, 완료 = 녹색 표시)만 색으로 남았다
- 「화사하게」(그 서비스의 첫 결정, 새 색 없음)를 큰 색 띠가 아니라 **선택·상태에만 색**으로 지켰다
- 의원·손님 화면이 기관명 머리 + 한 가지 일만 남은 1인 링크 틀이 됐다

## 적용하며 드러난 것 — 정본에 돌려줄 후보

1. **Tailwind v3 + shadcn 서비스의 길이 문서에 없다.** 결정 트리는 「Tailwind v4 → Tier 2 / 그 밖 → Tier 1」인데, v3 + shadcn 은 어느 쪽 절차와도 다르다. 이번에는 정본 CSS 를 import 하고 `ui/button` 만 `.ggc-btn` 에 대응시켰다 — quickstart 한 쪽감이다.
2. **팔레트를 통째로 바꾼 Tailwind 에서 색 없는 `border` 는 `currentColor`(검정 선)** 가 된다 — `borderColor.DEFAULT` 를 토큰으로 줘야 한다. 정본이 「Tailwind 기본 팔레트를 지우라」고 권한다면 이 한 줄도 함께 적을 일이다.
3. **`.ggc-actionbar` 의 음수 여백이 `.ggc-page-main` 패딩과 ≤480 에서 4px 어긋난다**(액션바는 `.ggc-shell-main` 기준값). 단폭 셸에서 바닥 띠 양옆에 틈이 생긴다.
4. **1인 링크 예외가 승인됐는데 검사기는 여전히 D3 WARN 4건을 낸다** — `.ggc-solo` 화면이면 대민 셸 항목을 건너뛰게 하면 경고가 「진짜 빠진 것」만 남는다.

캡처(표본 이름)와 서비스 쪽 결정 기록은 그 서비스 저장소의 `docs/design-decisions.md` 에 있다(이 저장소에는 옮기지 않는다).
