# 덜어내기 — 필요한 정보부터 보이게 한다 (v3.1, ADR 0012)

> 화면에 무엇을 **넣을지**가 아니라, 각 정보가 **언제 필요한지**를 정한다.
> 결정 근거는 [ADR 0012](../decisions/0012-show-what-is-needed.md). 눈으로 보려면 갤러리 [`less.html`](../../design/examples/less.html).

## 먼저 구분할 것 — 밀도와 정보 종류

- **밀도**는 같은 종류의 자료를 한 화면에 몇 건 보느냐다(행 높이·글자 크기). v3.0 이 정했고 바꾸지 않는다.
- **정보 종류**는 제목·설명·건수·상태·단계·안내·보조 패널처럼 서로 다른 묶음의 수다. 이 문서는 이것을 줄인다.

사용자 불만은 거의 다 두 번째였다. "칸이 크다"가 아니라 "보이는 것이 많다", "뭘 해야 하는지 모르겠다"였다.
**덜어내려고 글자를 작게 만들지 않는다.**

## 시작 질문 하나

> 이 화면을 연 사람은 **누구이고, 지금 무엇을 하러 왔나?**

이 답을 `design-decisions.md` 에 한 줄로 적고 시작한다. 한 줄이 안 나오면 화면이 둘이다.
목록을 보면서 문서를 고치는 일처럼, 한 일에 목록·문서 보기·입력이 함께 필요할 수는 있다.

## 규칙 10개

각 규칙에 **판정법**이 있다 — 사람이 화면을 보고 확인하는 방법이다. 검사기로 만들지 않는다.

### R1. 핵심 일과 먼저 누를 단추를 정한다
- 가장 강조하는 단추(`.ggc-btn--primary`)는 그 화면의 지금 맥락에서 **하나**다.
- 읽기·시청이 목적인 화면에는 주 단추를 억지로 만들지 않는다.
- **판정**: 처음 본 사람에게 "여기서 뭘 하는 곳인가요?"를 물어 한 문장이 나오는가. 행동이 필요한 화면이면 먼저 누를 단추를 3초 안에 찾는가.

### R2. 정보는 쓰임이 확인될 때 보인다
- 제목 아래 설명 · 요약 숫자 · 메타정보 · 보조 패널 · 인사말은 **기본 구성이 아니다.**
- 그 정보로 사용자가 무엇을 고르고·비교하고·확인하고·처리하는지 말할 수 있을 때 둔다.
- 늘 볼 필요가 없는 정보는 **조건이 될 때만** 나타난다 — 마감은 임박했을 때, 연결 상태는 끊겼을 때, 새 알림은 있을 때.
- 역할마다 필요한 것이 다르면 보이는 것도 다르다. 단, 화면에서 감추는 것으로 권한을 대신하지 않는다.
- **판정**: 그 영역을 가리고 대표 일을 따라가 본다. 판단이나 처리가 달라지지 않으면 뺄 후보다.

### R3. 같은 맥락의 정보는 한 곳에만
- 같은 범위의 기간·건수·상태·담당을 머리·띠·목록 줄·보기 칸에 되풀이하지 않는다.
- 모든 행에 같은 값이 있으면 그 값은 목록 위 한 곳으로 올린다.
- 따로 읽히는 곳(확인 창·인쇄물·내려받은 문서)에는 다시 적어도 된다.
- **판정**: 화면에서 같은 뜻의 글자를 형광펜으로 칠해 본다. 두 번 칠해지면 각 자리에 따로 확인할 이유가 있는지 묻는다.

### R4. 상태는 정확한 짧은 말로, 그림은 한 번만
- 상태는 실제 처리 결과와 맞는 짧은 말로 쓴다(`.ggc-badge`). 한 낱말에 맞추려고 뜻을 줄이지 않는다 — "배달 3 · 실패 0 · 확인 중 133"처럼 수량이 중요하면 대상과 단위를 함께 쓴다.
- **단계 막대·스텝퍼는 사용자가 단계를 직접 오가는 입력(Configure)과 사용 안내에만** 쓴다. 처리 경과 전체가 필요하면 상세에서 연다.
- 같은 상태를 배지 · 단계 막대 · 설명 문장으로 세 번 말하지 않는다. 끝난 일에는 배지 하나면 된다.
- **판정**: 색과 그림을 가리고도 상태를 읽을 수 있는가. 같은 상태가 두 가지 이상 그림으로 보이는가.

### R5. 판단에 필요한 안내는 그 자리에, 사용법은 단추 뒤로
- 입력 조건 · 이용 조건 · 실행 결과 · 오류 해결 방법은 **그 입력·단추 바로 옆**에 둔다.
- 단추와 제목을 되풀이하는 설명("여기서 보고를 작성할 수 있습니다")은 쓰지 않는다.
- 처음 쓰는 사람을 위한 사용법·따라하기는 **[사용 안내] 단추**로 연다. 자동으로 펼쳐 본문을 밀어내지 않는다.
- 낯선 용어나 선택지에는 **한 줄 풀이**를 붙인다(이건 덜어낼 대상이 아니다).
- **판정**: 안내를 읽어도 판단이 달라지지 않으면 줄인다. 처음 쓰는 사람이 실행 전에 알아야 할 조건은 보이는가.

### R6. 화면 틀과 현재 위치는 흔들리지 않는다
- 메뉴·검색·제목의 자리는 같은 화면군에서 같다. 검색하거나 조건을 걸어도 뒤로 단추·새 제목·빈 줄이 생기거나 사라지지 않는다.
- 제목은 화면군마다 **기본형**(본문 첫 줄에 h1) 또는 **간결형**(h1 을 눈에서만 숨김) 중 하나로 정한다 — 아래 「제목」 절.
- 0건이라는 이유만으로 메뉴를 자동으로 숨기지 않는다(서비스가 사용자와 정한 메뉴 정책은 그대로 둔다).
- **판정**: 처음 화면 · 검색 후 · 결과 없음 · 항목 선택 네 장을 나란히 놓고, 공통 조작부가 같은 자리에 있는지 본다.

### R7. 자주 쓰는 조작은 늘 같은 자리에, 가끔 쓰는 일은 이름으로 찾게
- 검색과 주요 조건은 한 줄에 모은다(넓은 화면 기준). 좁으면 읽기를 지키며 줄을 나눈다.
- **자주 쓰는 동작을 ⋯(더보기) 안에 숨기지 않는다.** 선택해야만 나타나는 단추는 사람들이 못 찾는다 — 위치는 늘 두고, 쓸 수 없을 때 이유를 알린다.
- 파일 올리기·일괄 처리처럼 **가끔 하는 한정된 일**은 이름 있는 단추로 창(모달)을 열고, 끝나면 원래 화면으로 돌아온다.
- **판정**: 항목을 고르기 전에도 주요 동작의 이름과 자리를 찾는가. 더보기·창을 키보드로 열고 닫은 뒤 하던 일을 이어 가는가.

### R8. 첫 결과와 작업 영역이 첫 화면에 보인다
- 목록 화면은 대표 화면 크기(업무 1440×900 · 휴대폰 390×844)에서 **첫 결과를 읽을 수 있다.**
- 결과가 없으면 그 이유(조건 때문인지, 자료가 없는지)와 다음 행동이 같은 자리에 보인다.
- 첫 결과를 밀어내는 장식 · 중복 설명 · 빈 여백을 먼저 줄인다. 행 수(15~20행)는 대조가 중심인 목록의 **참고 목표**다 — 통과 기준이 아니다.
- **판정**: 긴 제목이 든 대표 자료로 첫 화면을 찍는다. 첫 결과의 식별 정보가 읽히는가. 행 수를 늘리려고 글자·조작부를 줄인 흔적은 없는가.

### R9. 함께 대조하는 자료는 함께 보이게
- 목록을 고르며 문서를 확인하는 일은 **목록 + 문서 보기** 두 칸으로 둔다. 경계는 사용자가 끌어 바꿀 수 있고(키보드로도), 바꾼 폭은 기억하되 다음 방문에 칸이 사라지지 않게 한다.
- 문서의 서식이 판단 대상이면 글자만이 아니라 **실제 문서 모양**을 보여 준다. 넓은 화면의 남는 폭은 작업 칸에 준다.
- **판정**: 긴 목록과 긴 문서를 함께 열고, 확인을 위해 화면을 왕복하는지 본다.

### R10. 판단과 복구에 필요한 것은 덜어내지 않는다
- 입력 이름 · 현재 위치 · 오류 사유 · 복구 방법 · 저장 상태 · AI 결과의 출처는 남긴다.
- 초안·추정·확인되지 않은 결과를 확정된 것처럼 보이지 않는다(근거 없는 값은 비우고, 추정에는 "약"을 붙인다).
- 문자·메일처럼 **밖으로 나가는 것**은 대상과 실제 문안을 보여 주고 고친 뒤 보낸다. 되돌릴 수 없는 일은 따로 된 단추와 확인 창으로만 일어난다.
- **판정**: 실패 · 저장 안 됨 · 근거 없음 · 외부 발송 · 되돌릴 수 없는 동작 다섯 경우를 각각 눌러 본다. 무슨 일이 났고 어떻게 되돌리는지 아는가.

| 10 | 무엇을 하는지 한 줄로 설명할 수 없는 기능(보기 전환 등) | 넣지 않는다 | R1 |

## 제목 — 기본형과 간결형

ADR 0010 의 구조(h1 은 본문, 브레드크럼은 헤더)는 그대로다. **늘 보이는 큰 제목 줄**만 화면군마다 고른다.

- **기본형** — `.ggc-page-head` 에 h1 을 보인다. 레코드명(의안명·보고 제목)처럼 메뉴가 말해 주지 못하는 제목은 늘 기본형이다.
- **간결형** — 반복 작업 화면에서, 현재 화면 이름이 **작업 중 계속 보일 때만**(펼친 왼쪽 메뉴의 현재 항목·현재 탭). h1 은 `.ggc-sr` 로 남겨 화면 낭독기가 읽게 하고, 제목 줄의 공간을 함께 없앤다.
  접힌 메뉴의 아이콘만으로는 이 조건이 안 된다.
- 설명 줄(`.desc`)은 두 방식 모두 **기본 없음**. 주 액션은 핵심 행동이 있을 때만.
- 같은 화면군 안에서 검색·선택·자료 유무에 따라 방식을 바꾸지 않는다. **사용자가 이미 승인한 서비스의 제목 배치는 보존한다**(예: 모든 메뉴의 제목을 같은 자리에 둔 서비스).

```html
<!-- 간결형: 제목은 화면 낭독기만 읽는다. 첫 줄이 곧 작업 도구다 -->
<main class="ggc-shell-main" id="main" aria-labelledby="page-title">
  <h1 class="ggc-sr" id="page-title">내 보고</h1>
  <div class="… toolbar">…탭 · 검색 · [제출하기]…</div>
```

## 기존 서비스에 적용할 때

- **일괄로 바꾸지 않는다.** 그 화면을 다음에 고칠 때 적용한다. 확인된 오류·접근성 결함의 조치를 미루는 근거로 쓰지 않는다.
- 고치기 전에 `design-decisions.md` 에 적는다 — 이번에 바꿀 화면 범위 · 화면의 핵심 일과 쓰는 역할 · **이미 사용자가 승인한 결정** · 남길 것과 옮길 것.
- 검색 조건 · 저장 상태 · 출처 · 이력 · 업무 동작을 정리 과정에서 빠뜨리지 않는다. 인증·권한·데이터 구조 변경은 화면 정리 범위가 아니다.
- **화면을 통과시키려고 검사 항목·임계치를 낮추지 않는다.** 기준을 바꿀 때는 근거와 범위를 적는다.
- 전/후를 같은 자료·같은 화면 크기로 찍어 남긴다(`docs/design-evidence/`).

## 판정 목록 — 화면마다

`design-decisions.md` 의 「덜어내기 판정」 절에 **적용 · 미적용 · 해당 없음**으로 적는다. 개수로 합격을 정하지 않는다.

- [ ] 이 화면을 쓰는 사람과 핵심 일을 한 줄로 적었다
- [ ] 가장 강조한 단추가 하나다(읽기·시청 화면은 없어도 된다)
- [ ] 같은 뜻의 글자가 두 번 이상 보이지 않는다(따로 읽히는 곳 제외)
- [ ] 제목 아래 설명 줄·상시 안내 띠가 없다 — 있으면 그 쓰임을 적었다
- [ ] 단계 막대는 사용자가 단계를 오가는 입력·사용 안내에만 있다
- [ ] 검색·조건·주요 단추가 한 줄(넓은 화면)이고, 자주 쓰는 동작이 ⋯ 안에 없다
- [ ] 처음 · 검색 후 · 결과 없음 · 선택 후 네 장에서 머리 영역이 같다
- [ ] 대표 화면 크기에서 첫 결과(또는 작업 영역)가 보인다
- [ ] 모든 기능을 한 줄로 설명할 수 있다
- [ ] 오류 사유·복구·저장 상태·출처·외부 발송 미리보기가 남아 있다
