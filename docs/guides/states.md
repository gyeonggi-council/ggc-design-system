# 상태 보이기 — 기다림 · 저장 · 오류 · 빈 화면 · 알림 (v3.2, ADR 0013)

> 사용자가 "멈췄나?", "저장됐나?", "왜 안 눌리지?", "깨졌나?"를 묻지 않게 한다.
> GitHub Primer 의 UX 패턴(loading · saving · forms · empty states · degraded experiences · notification messaging)을
> 우리 업무(사무처 직원 · 24~32인치 모니터 · 회기 업무 · 결재)에 맞춰 옮겼다. 결정 근거는 [ADR 0013](../decisions/0013-github-tidy-and-shared-parts.md).
> 아래 시간·개수는 **기본값**이다 — 실제 처리량과 서버가 일을 이어갈 수 있는지가 먼저다. [덜어내기](less.md)와 함께 읽는다.

## 1. 기다림 — 얼마나 걸리나에 따라

| 걸리는 시간 | 보이는 것 | 부품 |
|---|---|---|
| 1초 미만 | 아무것도 그리지 않는다. **누른 것은 바로 받는다** — 단추를 잠가 두 번 실행을 막는다 | — |
| 1~3초 | 스피너(단추 안이면 작은 것) | [`.ggc-spinner`](../components/spinner.md) |
| 3초 넘음 · 이 화면에서 시스템이 하는 일 | 지금 단계 이름 · 경과 시간 · 센 값이 있으면 진행 막대 · 할 수 있으면 중지 | [`.ggc-job`](../components/job.md) · [`.ggc-progress`](../components/progress.md) |
| 10초 넘음 · 서버가 혼자 이어갈 수 있음 | 「창을 닫아도 계속됩니다」 + 끝나면 레코드 배지와 알림함 | `.ggc-job` |
| 목록·표 자리 | 골격 — 늦게(0.3초 뒤) 그린다. 목록 하나에 안내 한 번 | [`.ggc-skeleton`](../components/skeleton.md) |

- **진행률을 지어내지 않는다.** 막대는 센 값(6건 중 4건, 12쪽 중 5쪽)이 있을 때만. 단계 수(2/4단계)를 50%로 바꾸지 않는다. 마지막 단계를 모르면 막대를 거두고 「마무리하는 중 · 경과 3분」.
- **연결이 끊긴 것은 실패가 아니다** — 「진행 상태를 확인할 수 없습니다」(`data-state="unknown"`). 중지를 누른 것도 중지 완료가 아니다(`stopping`).
- **일부만 됐으면 일부만 됐다고** — 「12건 중 10건 완료 · 2건 실패」와 실패분만 다시 하는 길.
- **레코드의 처리 상태(접수 → 심사 → 가결)는 진행 표시가 아니다** — 배지 하나(§8). 단계 막대로 그리지 않는다([덜어내기 R4](less.md)).

## 2. 저장과 제출 — 다른 사건이다

| 무엇 | 어디에 | 문구 예 |
|---|---|---|
| 초안 저장(자동·수동) | 액션바 상태 칸 `.ggc-actionbar .status` — 좁은 화면에서도 숨기지 않는다 | 「초안 저장됨 · 14:32」 |
| 저장 실패 | 같은 자리, 위험색 + 다시 시도 · **입력은 그대로 둔다** | 「저장하지 못했습니다 · 입력은 그대로 있습니다 [다시 시도]」 |
| 제출 · 상신 · 발송 | 본문 맨 위 배너 `.ggc-alert--banner` — 시각과 건수를 남긴다(업무 근거) | 「3건 제출 완료 · 2026-10-24 14:35」 |
| 떠나려 할 때 저장 안 된 것이 있음 | 브라우저 확인(beforeunload) | — |

- 폼은 **명시 저장이 기본**이다. 자동 저장은 즉시 반영되는 컨트롤(스위치)과 이미 승인된 자동 저장 화면(예: 주간보고 작성)에만 — 한 폼에 섞지 않는다.
- 저장 단추를 숨기거나 끄지 않는다. 바뀐 것이 없으면 누를 때 「바뀐 내용이 없습니다」.
- 단추 이름은 동사로, 결과를 말한다 — 「저장」 「3건 제출하기」. 「확인」 「완료」 하나로 두지 않는다.

## 3. 폼 오류

- **제출할 때 검사한다.** 칸을 떠난 뒤(blur)부터는 그 칸을 다시 검사해도 된다. 입력 중에 빨간 글을 띄우지 않는다.
- 오류가 **셋 이상이거나, 화면 밖·접힌 영역에 있으면** 폼 맨 위에 요약 배너(오류마다 그 칸으로 가는 링크)를 두고 초점을 옮긴다. 그보다 적으면 첫 오류 칸으로 초점.
- 칸에는 `aria-invalid="true"` + `aria-describedby="오류 설명 id"` · 설명은 **무엇을 어떻게 고치나**(「숫자만 입력합니다 — 예: 01012345678」).
- 오류를 토스트로만 알리지 않는다. 오류 색만으로 알리지 않는다(아이콘·글 함께).

## 4. 못 쓰는 행동 — 이유를 보인다

`disabled` 단추는 키보드로 닿지 않고 이유도 말하지 않는다. 경우를 나눈다.

| 왜 못 쓰나 | 어떻게 |
|---|---|
| 아직 다 안 적었다 | 단추를 켜 두고, 누르면 §3 처럼 무엇이 빠졌는지 알린다 |
| 처리 중이다 | 실제로 막는다(두 번 실행 방지) — 단추 안 스피너 + 「제출하는 중」 |
| 권한이 없다 | 단추를 두지 않거나, 두면 가까이에 이유(「서무만 확정할 수 있습니다」) |
| 시스템 장애다 | 막고, 무엇이 안 되는지와 언제 다시 해 볼지를 가까이에(§6) |

체크·라디오처럼 고를 수 없는 항목은 `.sub` 에 이유를 적는다([check-radio](../components/check-radio.md)).

## 5. 빈 화면 — 넷을 가른다

| 경우 | 제목 | 행동 |
|---|---|---|
| 처음 — 아직 아무것도 없다 | 무엇이 없는지 | 만들기 하나 + 도움말 링크 하나 |
| 검색·필터 결과 없음 | 「"청년" 에 맞는 의안이 없습니다」 | **검색어·필터를 그대로 두고** 풀기 단추. 전체 건수를 적는다 |
| 일시적으로 비어 있다 | 「처리할 보고가 없습니다」 | 없으면 두지 않는다 |
| 불러오지 못했다 | 「일정을 불러오지 못했습니다」 + 오류 코드·시각 | 다시 시도 — **0건으로 보이지 않게**(`.ggc-empty--error`) |

부품은 [`.ggc-empty`](../components/empty.md). 장식 그림 대신 lucide 아이콘 하나.

## 6. 기능 저하 — 일부가 고장 났을 때

- **되는 부분은 그린다.** 셸(헤더·메뉴)은 절대 숨기지 않는다.
- 쓸 수 없는 것을 **지워진 것처럼 보이지 않게** — 「지금 불러올 수 없습니다(자료는 그대로 있습니다)」.
- 한 화면에 장애 안내는 다섯 개 이하 — 넘으면 본문 위 배너 하나로 묶는다.
- 꼭 필요하지 않은 건수(탭 숫자 등)는 못 불러오면 숨긴다. 장애 때문에 다른 컨트롤을 끄지 않는다.
- 화면 틀은 그대로 둔다([덜어내기 R6](less.md)) — 일부가 비었다고 배치가 뒤집히지 않게.

## 7. 알림을 어디에

| 알릴 것 | 자리 | 부품 |
|---|---|---|
| 한 칸·한 행동의 결과 | 그 칸·단추 바로 옆 | `.ggc-field .error` · 단추 옆 글 |
| 저장 상태 | 액션바 상태 칸 · 휴대폰 1인 링크 화면은 바닥 띠 상태 칸 | `.ggc-actionbar .status` · `.ggc-solo-bar .status` |
| 화면 전체의 결과(제출 · 발송 · 장애) | 본문 맨 위 배너 | `.ggc-alert--banner` |
| 되돌릴 수 없는 일의 확인 | 모달 | `.ggc-modal--alert` |
| 결과가 화면에 안 보이는 짧은 확인(복사됨) · 실행 취소 제안 | 토스트 — 예외다 | [`.ggc-toast`](../components/toast.md) |
| 오래 걸린 작업이 끝남(그 화면을 떠난 뒤) | 레코드 배지 + 알림함 | `.ggc-badge` |

- **성공 메시지는 아낀다** — 결과가 화면에 그대로 보이면(목록에 새 행이 생김) 따로 알리지 않는다. 다만 제출·결재 결과는 업무 근거라 남긴다.
- 메시지는 **무슨 일이 · 왜 · 다음에 무엇을** 순서로 짧게. 오류 코드와 시각은 끝에.

## 8. 상태 사전 — 같은 상태는 같은 모양

**업무 상태**(레코드가 어디까지 왔나)와 **작업 상태**(시스템이 지금 하는 일)는 다른 축이다. 「승인」 「제출 완료」 「변환 완료」를 모두 「완료」로 합치지 않는다 — 글이 다르다.

| 뜻 | 배지 | 아이콘 | 업무 상태 예 |
|---|---|---|---|
| 끝났다 · 좋은 쪽 | `--approved` | `circle-check` | 승인 · 가결 · 제출 완료 · 지급 결정 |
| 사람의 차례를 기다린다 | `--pending` | `clock` | 접수 · 검토 대기 · 서무 확인 중 |
| 끝났다 · 나쁜 쪽 | `--rejected` | `circle-x` | 반려 · 부결 · 기한 넘김 |
| 진행되는 사실을 알린다 | `--session` | `circle-dot` | 회기 중 · 방송 중 |
| 멈춤 · 해당 없음 | `--recess` | `circle-minus` | 보류 · 비회기 · 철회 |
| 돈이 나갔다 | `--paid` | `circle-check` | 지급 완료 |

작업 상태(진행 중 · 중지 요청 중 · 확인 불가 · 일부 실패)는 [`.ggc-job`](../components/job.md) 의 `data-state` 가 맡는다. 배지는 늘 글과 함께(색 단독 금지).

## 9. 상자 하나에 행 목록

GitHub 의 목록은 **테두리 상자 하나 안에 행**이다. 우리도 그렇게 한다(`.ggc-card` + `.ggc-card-head` + `.ggc-list-row`).

- 행 목록에서 항목마다 카드를 따로 두지 않는다. 카드 안에 카드를 두지 않는다.
- 행마다 **같은 아이콘 받침을 반복하지 않는다** — 종류가 섞여 아이콘이 구별을 돕는 목록에만 둔다.
- 서로 다른 작업 단위(독립된 문서·작업대의 두 칸)는 상자를 나눠도 된다 — 이 규칙은 **행 목록**에 대한 것이다.
- 행의 동작은 마지막 열에. 가장 자주 쓰는 하나만 밖에 두고 나머지는 메뉴([덜어내기 R7](less.md)). 숫자 열은 오른쪽 정렬, 기본 정렬 열은 하나.

## 10. 판정 — 화면을 고칠 때

- [ ] 3초 넘게 걸리는 일에 지금 단계와 경과가 보이는가 · 진행률이 센 값인가
- [ ] 연결이 끊겼을 때 「실패」가 아니라 「확인할 수 없음」으로 보이는가
- [ ] 저장 상태가 좁은 화면에서도 보이는가 · 실패해도 입력이 남는가
- [ ] 제출·발송 결과가 시각과 함께 화면에 남는가(토스트로만 알리지 않는가)
- [ ] 못 누르는 단추마다 이유가 가까이 있는가
- [ ] 「결과 없음」과 「불러오지 못함」이 다르게 보이는가
- [ ] 같은 상태가 서비스 안에서 같은 배지·아이콘인가

확인하지 못한 항목은 「미확인」으로 적는다.
