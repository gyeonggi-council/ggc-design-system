# PC·모바일 UI/UX 검토 및 개선

## 발견한 문제

1. **모바일 주요 화면의 메뉴 누락**: 대시보드·의안 목록·위저드에 메뉴 트리거와 공통 동작 로드가 없었다. 메뉴가 있는 화면도 닫힌 내비게이션에 키보드 포커스가 진입했다.
2. **가로 넘침**: 의안 목록은 390px에서 343px 초과했다. 화면 폭보다 넓은 고정 격자·표의 숨긴 헤더 셀·툴팁·긴 코드 문자열도 발견했다.
3. **낮은 업무 밀도**: 모바일 대시보드는 첫 업무 항목이 1,131px, 의안 목록은 1,016px 아래에서 시작했다. 개발자용 안내·세로로 쌓인 통계·펼쳐진 필터가 상단을 차지했다.
4. **표시만 있는 동작**: 검색·페이지 이동·엑셀 버튼·단계 이동이 실제 상태를 바꾸지 않았다. 위저드의 저장 표시도 고정된 문구였다.
5. **작성과 참고 자료 분리**: 모바일 참고 자료가 전체 입력 폼 아래로 내려갔다. 카드 패딩과 맞지 않는 음수 여백, 중복 진행 표시, 문서 하단의 이동 버튼도 있었다.
6. **합본 상호작용**: 검색창 ID가 다른 데모와 충돌했다. 입력 직후 결과를 누르면 blur에 의한 재렌더로 첫 클릭이 사라지는 문제를 동작 검사에서 찾아 수정했다.

## 수정

- 정본의 메뉴에 PC 접기, 모바일 닫기·배경·Escape·Tab 순환·포커스 복귀·리사이즈 잠금 해제를 추가했다.
- `.ggc-work`를 추가해 제목·검색·실제 업무를 먼저 배치했다. 통계는 모바일 두 열, 업무와 참고 자료는 전환 버튼으로 접근한다.
- 목록은 검색·조건·정렬·페이지 이동·전체 상세·CSV 다운로드를 구현했다. PC 표와 모바일 카드가 동일한 21개 의안을 공유하며 8개 정보 열을 모두 제공한다.
- 초안은 네 단계, 입력 보존, 추가 조문, 임시저장·새로고침 복원, 필수 입력 검사, 텍스트 내보내기를 지원한다. 실제 제출 API는 호출하지 않는다.
- 로컬 Pretendard GOV를 연결하고 생성기에서 오프라인 합본에 포함했다. 새 브랜드색은 추가하지 않았다.
- README 미리보기, 합본, DESIGN.md를 정본에서 다시 생성했다. 브라우저 검증을 GitHub Actions에 추가했다.

## 검증 범위

`node tools/check-responsive.cjs`: 14개 갤러리 페이지와 합본 × 6개 폭 = 90조합.
가로 넘침과 브라우저 오류를 검사한다. 별도 동작 검사에서는 PC·모바일 검색, 조건, 초기화,
빈 결과, 정렬, 21건 전체 순회, 8개 상세 항목, CSV, 단계 전환, 참고 자료 접근,
저장·복원, 추가 조문, 필수 입력 포커스, 초안 내보내기와 합본 페이지 이동을 확인한다.
PC 1440×900에서는 목록 15개 행이 첫 화면 안에 들어오는지 검사한다.

`bash tools/check-all.sh`: 정본 strict, 업무·대민 갤러리, 문서 링크, Tier 2 레지스트리 검사를 수행한다.
범위는 이 디자인 시스템과 예제다. 실제 소비 서비스 배포, 실제 휴대폰의 OS·키보드 조합,
백엔드 제출·권한 처리는 이 검증에 포함하지 않는다.
