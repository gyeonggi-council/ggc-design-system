## 2. 공통 레이아웃 패턴

### 2.1 유틸리티 바 (전 시스템 최상단 필수)
높이 ~32px, 배경 `--ggc-secondary`. 좌측 기관명, 우측 통합서비스 스위처.

```
┌──────────────────────────────────────────────────────────────┐
│ 경기도의회 의정정보시스템        통합서비스: [입법역량지원*] [의사일정관리] [하이패스 경비정산] │
└──────────────────────────────────────────────────────────────┘
```
- 현재 시스템은 `active`(primary 배경) 표시.
- 스위처 항목(2026-07-12 기준 5개): 입법역량지원(내부망) · 의안처리(내부망) · 의사일정관리(`(내부 안내 참조)`) · 하이패스 경비정산(`(내부 안내 참조)`) · 도의원 인사관리(배포 URL 확정 시 추가).
- **내부망 규칙**: 내부 시스템(플랫폼·BIMS)끼리는 실링크(localhost), 외부 배포 앱(Vercel)에서는 내부 시스템을 `span.disabled` + "(내부망)" 표기.
- 마크업/스타일: `design/ggc-tokens.css`의 `.ggc-utility-bar` 사용.
- **BIMS 팔레트 예외**: BIMS 본문은 공식 CI(#3C5D89, ggc.go.kr Pantone 653C — 공통 토큰 #3C5D93과 시각적으로 동일)를 유지하고, 유틸리티 바 등 공통 요소만 공통 토큰을 쓴다.

### 2.2 서비스 헤더
유틸리티 바 아래, 흰 배경 + 하단 1px `--ggc-gray-30` 경계. 좌측에 서비스명(예: "의사일정 관리시스템") `--ggc-gray-90` 볼드, 우측에 로그인 사용자·로그아웃.

### 2.3 상태 배지
결재 상태·회기 판정 등 모든 상태 표기는 `.ggc-badge` 알약형으로 통일:
- 회기 중 `--session`(파랑) / 회의일 `--meeting`(초록) / 비회기 `--recess`(회색)
- 승인·확정 `--approved`(초록) / 대기·상신 `--pending`(호박) / 반려 `--rejected`(빨강)

### 2.4 푸터
`--ggc-gray-10` 배경: "경기도의회 의회사무처 공간정보화과 · 통합 의정정보시스템" + 관련 링크.

## 4. 의사일정 공통 서비스 연동 규칙

의사일정 데이터(확정분)는 전 시스템의 공통 참조 서비스다.

- **데이터 소스**: 같은 공용 DB 내 시스템(하이패스)은 `public.assembly_sessions`·`public.v_schedule_events`(status='confirmed') 직접 SELECT. 외부/온프레미스 시스템(입법역량지원 플랫폼 등)은 공개 API `(내부 안내 참조)/api/v1/{sessions,events}` 사용.
- **회기 판정 규칙**(하이패스 경비정산 적용):
  - 일자가 확정 회기(`assembly_sessions.start_date~end_date`) 안 → **회기 중**
  - 일자에 확정 일정 항목(본회의 또는 해당 의원 소속 위원회 회의) 존재 → **회의일**
  - 그 외 → **비회기**
- **판정은 심사 참고 정보(advisory)로만 표시**하고 지급 가부를 시스템이 강제하지 않는다. 근거: 위원회별 운영 방침이 다르고, **위원장 등은 회기 외에도 상시 등청하는 관행**이 있으므로 최종 판단은 전문위원실·회계 담당자가 한다.
