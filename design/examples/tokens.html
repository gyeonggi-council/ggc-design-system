토큰 · 팔레트ggc-tokens.css v2.0

아래 모든 색값과 대비비는 이 페이지가 열릴 때 브라우저가 계산한 것이다. 마크업에는 토큰 이름만 있고 숫자가 하나도 없다 — getComputedStyle 로 정본을 읽어 채운다. 그래서 이 표는 낡을 수 없다.

고대비를 켜고 다시 보라. 브라우저·OS 에서 prefers-contrast: more 를 켜면 중립 램프가 한 단계 진해지고 숫자가 즉시 따라 바뀐다. 팔레트를 하나 더 만든 것이 아니라 같은 이름의 미디어 오버라이드이기 때문이다.

브랜드 경기도의회 네이비

KRDS 기본 파랑을 기관 CI 로 오버라이드한 체계다. KRDS 가 전제하는 사용법이며, 폐기값 #256ef4·#246beb 는 검사기가 발견 즉시 FAIL 로 잡는다.

상태 자기 틴트 위 · 흰 위 양쪽 AA

v1.1 은 네 색 전부 자기 틴트 위에서 3.65~3.83:1 이라 미달이었다. v1.2 는 색상각을 유지한 채 명도만 낮춰 AA 를 넘겼고, 흰 위에서도 5.2:1 이상이라 연한 배지와 채움 버튼 양방향으로 쓸 수 있다.

틴트 (배경 전용)

색 단독에 의존하지 않는다. 아래처럼 배지에는 항상 텍스트나 아이콘을 함께 둔다. 색각 이상 사용자에게는 대비만으로 부족하고, 이것은 대비 수치와 무관하게 지켜야 한다.

✓ 승인 ◷ 대기 ✕ 반려 ● 회기 중 ◆ 회의일 ○ 비회기 ₩ 지급완료

중립 텍스트 램프 4단 + 본문 단락 1 + 비텍스트 1

네 단 전부 흰 배경과 페이지 배경 양쪽에서 AA 를 넘고 단조성이 유지된다. 아래 두 번째 대비값이 페이지 배경 --ggc-bg 위 값이다.

--ggc-text-faint 를 텍스트에 쓰면 AA 미달이다. 이름이 램프의 다섯 번째처럼 보이지만 아니다 — v1.1 의 --ggc-text-subtle 이었고 정본 최다 사용색이라 삭제하지 않고 비텍스트 전용으로 역할만 강등했다. 3:1 대상(아이콘·구분선)에만 쓴다.

면 · 선

전부 배경·테두리 전용이다. 대비 판정 대상이 아니라 대비비를 표시하지 않는다.

역할 색쌍 신원 — 상태와 다른 축이다

“누구인가”를 나타낸다. 결재 상태(승인/반려)와 겹쳐 쓰지 않는다 — 한 화면에서 두 축이 같은 색을 쓰면 배지 하나가 두 가지로 읽힌다.

의원 사무처 정책지원관 기타

금/앰버를 역할 배지 밖으로 확산시키지 않는다. 확산하면 플랫폼에 주 색상이 하나 더 늘고, 그게 지금까지 색이 여덟 종으로 벌어진 기제다.

타이포그래피 --ggc-font · --ggc-font-mono

자체 호스팅이다. Pretendard GOV 를 서비스가 직접 담고 @font-face 를 선언한다. 외부 CDN 을 링크하지 않는다 — 망분리 환경에서 요청이 나가지 않아 글꼴이 폴백으로 떨어진다. 이 저장소도 폰트 파일을 담지 않으므로 아래는 폴백 체인으로 보일 수 있다.

간격 --ggc-space-1 ~ -11

v1.1 에는 간격 토큰이 아예 없어 각 서비스가 px 를 직접 썼다. 1~7 은 디자인 원본 실측 최빈값이고, KRDS semantic.gap 의 부분집합과 일치한다. v2.0 의 8~11 은 KRDS 의 다음 스텝(40·48·64·80)을 그대로 가져왔다 — 사이 값을 발명하지 않는다.

형태 · 그림자 · 포커스

그림자 — 카드는 그림자를 쓰지 않는다 (계약 §2). primary 버튼만 예외다
--ggc-shadow
기본 · 거의 보이지 않는다
포커스 링 — --ggc-focus-ring

아래 세 컨트롤에 Tab 으로 들어가 보라. 디자인 원본은 outline:none 을 28곳에 두고 대체를 두지 않았다 — 그대로 이식하면 KWCAG 2.2 / WCAG 2.4.7 위반을 전 시스템에 복제한다. 이 지점에서는 원본을 따르지 않는다.

링크

forced-colors 에서 box-shadow 는 렌더되지 않는다. 포커스 링을 그림자로만 만들면 Windows 고대비 사용자에게 통째로 사라진다. 실제로 그런 상태였고, 토큰이 outline: 3px solid Highlight 로 복원한다. 포커스·선택·현재 단계를 그림자로만 나타내지 말 것.

셸 치수 계약 §2

--ggc-gnb-h64px — GNB 높이. sticky, 하단선 --ggc-shell-border
--ggc-lnb-w256px — LNB 폭. GNB 브랜드 슬롯과 같은 폭이라 세로선이 이어진다
--ggc-main-max1320px — 대시보드 본문 최대폭
--ggc-main-max-wide1360px — 기타 업무 화면 (.ggc-shell-main--wide)

≥1680px 에서 1560/1600 으로 확폭되고, 1679px 이하는 수치가 그대로 보존된다 — 기존 1440×900 검증 증적과 Windows 125% 배율 FHD(뷰포트 1536px)가 확폭의 영향을 받지 않게 하기 위한 의도된 동작이다.

≤900px 에서 LNB 가 drawer 로 접힌다. 이 규칙은 디자인 원본에 근거가 없다 — 원본은 @media 0건이고 시안이 전부 1440 데스크톱이다. 계약 §2 를 근거로 여기서 1회 정의해 공통으로 고정했다. 창을 좁혀 보면 동작을 확인할 수 있다.

컨트롤 치수 · 밀도 · 대민 프로필 v2.0 · 계약 §9

업무용과 대민용이 같은 토큰 파일 하나를 쓴다. 기본(속성 없음)이 업무 프로필이고, 대민 화면은 <html data-ggc-profile="public"> 한 줄로 켠다. 프로필이 바꾸는 것은 아래 치수뿐이다 — 색·포커스·서체·간격은 건드리지 못한다 (검사기 D6 가 허용 목록으로 막는다). 대민 값은 KRDS 토큰에서 기계적으로 옮겼다.

누르면 이 페이지 전체가 대민 치수로 바뀌고, 아래 표의 값이 즉시 따라 바뀐다. 색 스와치와 대비비는 그대로다.
