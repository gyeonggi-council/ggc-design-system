# 대민 화면 패턴 — 무엇으로 어떤 순서로 채우는가

업무 화면의 Surface Archetype(`archetypes.md`)에 대응하는 **대민(공개) 화면 6종**이다.
판정은 성격이 아니라 **구성요소**로 한다. 셸은 전부 같다(`docs/guides/public-shell.md`) —
마스트헤드 → 헤더 → 본문 → 공개 푸터. 아래는 본문(`.ggc-public-main .inner`) 안의 처방이다.

| 패턴 | 판정 | 실물 |
|---|---|---|
| **메인** | 히어로(검색 + 바로가기)가 있고 본문이 섹션 묶음이다 | `design/examples/public/index.html` |
| **목록** | 검색 조건 + 결과 요약 + 표(또는 구조화 목록) + 페이지네이션 | `public/list.html` |
| **상세** | 단일 레코드 — 키-값 표 + 본문(탭) + 다음 행동 | `public/detail.html` |
| **서식** | 단계 표시 + 폼 + 동의 + 제출 | `public/form.html` |
| **검색** | 통합검색 결과 — 유형별 묶음 + 필터 | (목록 패턴의 변형) |
| **안내** | 긴 글 — 절차 · 자격 · 담당 · 연락처 | (상세 패턴의 `--doc` 변형) |

---

## 메인

**격자** — `.ggc-public-main` 에 `padding-top: 0` 을 주고 `.ggc-hero` 를 가득 폭으로, 그 아래 `.inner`.

| # | 슬롯 | 컴포넌트 | 개수 |
|---|---|---|---|
| 1 | 히어로 | `.ggc-hero` — h1 + 안내 한 줄 + 통합검색 폼 + 바로가기 칩 4~6 | 1 |
| 2 | 긴급/회기 공지 | `.ggc-alert--banner` | 0~1 |
| 3 | 진행 중인 참여 | `.ggc-structured-list` 3~6 | 1 |
| 4 | 이번 주 일정 | `.ggc-table` (일시 · 회의 · 장소 · 안건 · 방송) | 1 |
| 5 | 새 소식 | `.ggc-card` + `.ggc-list-row` 3~5 + "전체 보기" | 1 |

**세 상태** — 참여 공모가 0건이면 섹션을 숨기지 말고 "진행 중인 공모가 없습니다. 지난 공모 결과 보기" 로.
**하지 말 것** — 배너 캐러셀(KRDS 는 허용하나 접근성 부담이 크다, P2 보류) · 섹션 7개 이상 · 히어로에 사진 배경.

## 목록

**격자** — `.inner.ggc-public-main--side` (사이드 내비 240 + 본문). 사이드 메뉴가 3개 미만이면 `.inner` 단일.

| # | 슬롯 | 컴포넌트 |
|---|---|---|
| 1 | 페이지 타이틀 | `.ggc-page-title` (브레드크럼 + h1 + 설명) |
| 2 | 검색 조건 | `.ggc-card--pad` 안 `.ggc-field`(검색어 · 셀렉트) + `.ggc-chip` + 검색/초기화 |
| 3 | 결과 요약 | "검색 결과 총 N건 · 조건" |
| 4 | 결과 | `.ggc-table`(식별자 · 제목(링크) · 소관 · 일자 · 상태 배지) 또는 `.ggc-structured-list` |
| 5 | 페이지네이션 | `.ggc-pagination` + `.summary` |
| 6 | 절차 안내 | `.ggc-alert` 중립 (선택) |

**세 상태** — 빈 결과: "조건에 맞는 의안이 없습니다. 검색어를 줄이거나 기간을 넓혀 보세요" + 초기화 버튼.
오류: 표 자리에 `.ggc-alert--danger` + 다시 시도. 로딩: `.ggc-skeleton` 행 유지.
**하지 말 것** — 상태를 색만으로 · 전량 렌더 · 표를 390 에서 가로 오버플로(래퍼 필수).

## 상세

| # | 슬롯 | 컴포넌트 |
|---|---|---|
| 1 | 페이지 타이틀 | h1 = 레코드 제목, `.desc` 에 식별자 + 상태 배지 |
| 2 | 기본 정보 | `.ggc-table--kv` (5~8행) |
| 3 | 본문 | `.ggc-tabs` — 첫 탭은 `.ggc-prose`, 경과는 `.ggc-list-row`, 첨부는 목록 + 내려받기 |
| 4 | 참여 유도 | `.ggc-alert--info` + 주 액션 (의견 제출 · 방청 신청) |
| 5 | 이동 | ← 목록 · 인쇄 |

**하지 말 것** — 주 액션 둘 이상 · 첨부 파일 형식·용량 생략 · 사람 이름 실명(공개 화면은 `○○○ 의원`).

## 서식

| # | 슬롯 | 컴포넌트 |
|---|---|---|
| 1 | 페이지 타이틀 | 무엇을 · 언제까지 · 결과는 어떻게 |
| 2 | 단계 | `.ggc-wizard` 3단 (작성 → 확인 → 완료) |
| 3 | 입력 묶음 | `.ggc-card--pad` 여러 개 — 제출자 · 내용 · 동의. 카드 하나에 필드 6개 이하 |
| 4 | 동의 | `.ggc-prose` 고지문 + `.ggc-check`(필수) |
| 5 | 처리 안내 | `.ggc-alert` 중립 — 배정 기한 · 결과 통지 방법 · 처리 현황 링크 |
| 6 | 제출 | 취소(secondary) → 다음/제출(primary, `--lg`) 우측 정렬. 대민은 스티키 액션바를 쓰지 않는다 |

**세 상태** — 검증 오류: 첫 오류 필드로 포커스 + `.error` 문구에 사유("20자 이상 · 현재 0자"). 제출 중: 버튼 비활성 + 스피너.
완료: 접수번호 + 처리 기한 + "처리 현황 보기".
**하지 말 것** — placeholder 만으로 라벨 · 동의 없이 개인정보 수집 · 파일 형식·용량 미고지 · 뒤로 가면 입력 잃기.

## 검색 (통합검색 결과)

목록 패턴에 **유형 탭**(`.ggc-tabs`: 전체 · 의안 · 회의록 · 의원 · 소식)을 얹는다. 각 유형은 3건 미리보기 + "더 보기".
검색어는 결과 문구와 입력창 양쪽에 남긴다.

## 안내 (절차 · 자격 · 담당)

상세 패턴에서 본문을 `.ggc-prose` 로만 채운다. 절차는 `.ggc-wizard--vertical`, 자격·서류는 표, 담당은
`.ggc-table--kv`(부서 · 전화 · 이메일 · 운영시간). **연락처가 없는 안내 페이지는 완성이 아니다.**

---

## 공통 — 모든 대민 패턴

- **문장은 존댓말(–합니다)**, 쉬운 공공언어. 전문 용어에는 풀이 한 줄(예: "회부 — 위원회에 심사를 맡기는 것").
- **날짜는 `YYYY-MM-DD`**, 요일은 괄호. 상대시간 금지.
- **개인정보**: 수집 항목 · 목적 · 보관 기간 · 미동의 시 불이익을 서식 안에 적는다(「개인정보 보호법」 제15조).
- **연락처**: 안내·서식 페이지에는 담당 부서와 대표전화가 있어야 한다.
- **터치 대상 44px 이상** — 대민 프로필 컨트롤 48px 가 이를 보장한다. 링크 간격도 8px 이상.
- **인쇄를 가정한다** — `ggc-public.css` 의 `@media print` 가 셸을 걷어낸다. 본문에 기관명·출력일시를 남긴다.
- 사람 이름은 `○○○`, 의원은 `○○○ 의원`. 직원 실명은 담당 연락처에만.
