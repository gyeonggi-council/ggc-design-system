## 착수 전 — 기준선을 먼저 고정한다

**되돌릴 지점이 없으면 리스킨을 시작하지 않는다.**

```bash
python <저장소>/design/check_design.py --report <서비스경로> \
       > <서비스경로>/docs/design-baseline.txt
```

1. 위 리포트(현재 팔레트 전량 + 형 판정)를 파일로 남긴다
2. **1440×900 · 390×844 스크린샷**을 주요 화면마다 찍어 둔다 — 시각 회귀 판정의 유일한 근거다
3. 서비스별 로컬 git 에 **리스킨 착수 직전 커밋**을 만든다
4. 가동 중이면 현재 이미지 태그를 적어 둔다(롤백 좌표)

## ❹ 독자형의 절차 — 역방향 매핑표를 먼저 만든다

**표 없이 일괄 `sed` 하지 않는다.** 색 하나가 두 가지 의미로 쓰이는 경우가 흔하다.

1. 검사기 리포트에서 이 서비스가 쓰는 색을 전부 뽑는다
2. **각 색이 무슨 의미로 쓰였는지** 확인하고 토큰 이름을 배정한다

   | 현재 | 쓰인 자리 | → 토큰 |
   |---|---|---|
   | `#0b4da2` | 주 버튼·링크 | `--ggc-primary` |
   | `#0b4da2` | 헤더 배경 | `--ggc-primary-deep` ← **같은 색인데 다른 토큰이다** |

3. 표를 **사용자에게 보이고** 확인받는다
4. 치환하고 스크린샷을 전후 비교한다
5. 남는 색은 토큰으로 못 가는 것이다 — `ggc-design-allow` 로 등록하거나 정본에 승격 요청

## ❸ 인라인형이 가장 쉽다

`ggc_ai_hipass`·`ggc_ai_hr` 은 **값이 이미 맞다.** 그러니 **값을 건드리지 않는다.**

1. `ggc-tokens.css` 를 복사해 자기 스타일보다 먼저 로드 (→ D1 성립)
2. 하드코딩 hex 를 `var(--ggc-*)` 로 **치환만** 한다 — 값이 같으므로 **렌더 결과가 바뀌지 않는다**
3. D1·D2 가 둘 다 통과한다

**시각 회귀 위험 0이라 도입 저항이 없다.** 여기부터 하면 게이트가 먼저 초록이 된다.

## 위험이 실재하는 곳

### `ggc-ai-live-transcribe` — 세 겹

1. `frontend/public/favicon.ico` 는 **ICO 가 아니다.** 매직 바이트가 `89 50 4E 47`(PNG)이고
   ICO 디렉터리로 읽으면 `type=18254, count=2573` 이라는 쓰레기가 나온다. 60,733 바이트짜리
   PNG 에 `.ico` 확장자를 붙인 파일이다. **삭제 대상.**
2. `src/app/favicon.ico`(정상 ICO) + `src/app/icon.png`(**512×512, 203KB**)가 공존해
   페이지마다 `rel="icon"` 이 2개씩 나온다(20페이지 × 2 = 40건). 512 PNG 는 **모든 페이지에서
   실제로 다운로드된다** — 16px 탭 하나에 200KB 다. 32 로 교체하면 성능이 개선되지만
   **눈에 띄는 변화**라 "아이콘이 흐려졌다" 는 반응이 나올 수 있다.
3. **오리진이 둘이다** — `27.96.x.x/transcribe/` 와 `aisub.ggc.go.kr/transcribe/`.
   후자의 루트 `/favicon.ico` 를 무엇이 받는지 Traefik 라우팅을 확인해야 한다.
   `ggc-poc-web` 이 안 받는다면 그 호스트에는 루트 폴백이 없다.

### `award_office` — theme-color 가 눈에 보인다

`#13778e`(청록) → `#3C5D93`(네이비)는 모바일 주소창 색이 바뀌는 변화다. 이 서비스는
팔레트 전체가 청록으로 드리프트해 있어서, **파비콘·theme-color 만 네이비로 바꾸면 오히려
부조화가 도드라질 수 있다.** 파비콘을 먼저 가고(가역적·범위 작음) 색 통일을 뒤에 붙인다.

### `bill-system` — 명시적 예외를 선언한다

eGovFrame WAR 무수정 원칙과 리스킨이 충돌한다. `custom.css` 2,620줄에 계약 §6 의 BIMS
특별 규칙까지 걸려 있다. **시각만 수렴하고 기능·JSP 매핑은 건드리지 않는다.**
수렴이 불가능한 부분은 `ggc-design-allow` 로 **등록**한다 —
조용히 FAIL 로 남겨 두면 게이트 전체가 신뢰를 잃는다.

`src/main/webapp/rhwp/` 벤더 번들은 손대지 않는다(재빌드하면 덮어써진다).

### `ggc-poc-web` — 도면은 예외다

`webapp/styles/document.css` 의 색은 **범례**다(공개 영역 / 사설 영역 / 차단).
브랜드색을 밀어 넣으면 도면이 읽히지 않는다. **셸(`hub.css`)만 수렴**하고 도면 본문은
`ggc-design-allow` 로 등록한다.

> 참고: `design-system.md` 는 "셸은 토큰을 따른다" 고 서술했지만 실측하면 `hub.css` 의
> `--ggc-*` 참조는 **0회**다. 색 배제 원칙 자체는 지켜졌지만(새 색을 안 만들고
> `--ink`/`--rule`/`--surface` 재사용) 그 토큰 체계가 `--ggc-*` 가 아닐 뿐이다.
> 리스킨의 실제 작업은 **이름을 `--ggc-*` 로 옮기는 것**이다.
