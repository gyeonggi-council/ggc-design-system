# 가동 중 서비스를 정본으로 수렴시키기 (❹ 독자형 · 상황 B)

이미 돌아가는 서비스에 정본을 입히는 절차다. 신규 서비스는 `SKILL.md` Phase 2 로 바로 간다.
2026-08 플랫폼 서비스별 실측(무엇이 갈라져 있었나 · 순서 · 위험)은 `docs/migration/platform-services-2026-08.md`.

## 착수 전 — 기준선을 먼저 고정한다

**되돌릴 지점이 없으면 리스킨을 시작하지 않는다.**

```bash
python "$ROOT/design/check_design.py" --report <서비스경로> > <서비스경로>/docs/design-baseline.txt
```

1. 위 리포트(현재 팔레트 전량 + 형 판정)를 파일로 남긴다
2. **1440×900 · 390×844 스크린샷**을 주요 화면마다 찍어 둔다 — 시각 회귀 판정의 유일한 근거다
3. 서비스 저장소에 **리스킨 착수 직전 커밋**을 만든다
4. 가동 중이면 현재 배포 태그를 적어 둔다(롤백 좌표)

## ❹ 독자형의 절차 — 역방향 매핑표를 먼저 만든다

**표 없이 일괄 `sed` 하지 않는다.** 색 하나가 두 가지 의미로 쓰이는 경우가 흔하다.

1. 검사기 리포트에서 이 서비스가 쓰는 색을 전부 뽑는다
2. **각 색이 무슨 의미로 쓰였는지** 확인하고 토큰 이름을 배정한다

   | 현재 | 쓰인 자리 | → 토큰 |
   |---|---|---|
   | `#0b4da2` | 주 버튼·링크 | `--ggc-primary` |
   | `#0b4da2` | 헤더 배경 | `--ggc-primary-deep` ← **같은 색인데 다른 토큰이다** |

3. 표를 **사용자에게 보이고** 확인받는다
4. 치환하고 스크린샷을 전후 비교한다
5. 남는 색은 토큰으로 못 가는 것이다 — `ggc-design-allow` 로 등록하거나 정본에 승격 요청
6. 네임스페이스가 다른 토큰(`--gg-*` · `--gac-*` 등)은 값이 같아도 **이름을 `--ggc-*` 로 옮긴다** — 이름이 인터페이스다

## ❸ 인라인형이 가장 쉽다

값이 이미 맞다. 그러니 **값을 건드리지 않는다.**

1. 정본 파일을 복사해 자기 스타일보다 먼저 로드 (→ D1 성립)
2. 하드코딩 hex 를 `var(--ggc-*)` 로 **치환만** 한다 — 값이 같으므로 **렌더 결과가 바뀌지 않는다**
3. D1·D2 가 둘 다 통과한다

**시각 회귀 위험 0이라 도입 저항이 없다.** 여기부터 하면 게이트가 먼저 초록이 된다.

## 위험이 실재하는 자리 — 유형

| 유형 | 무엇이 일어나나 | 어떻게 |
|---|---|---|
| **theme-color 가 눈에 보인다** | 팔레트 전체가 다른 색조로 드리프트한 서비스에 파비콘·theme-color 만 바꾸면 부조화가 도드라진다 | 파비콘 먼저(가역적), 색 통일은 뒤에 |
| **아이콘 선언 중복** | Next 의 `app/favicon.ico` + `app/icon.png` 공존 → 페이지당 `rel=icon` 2개 | `icon.png` 만 남긴다(`porting.md`) |
| **벤더 번들** | 자체 `<head>`·매니페스트를 가진 뷰어 번들이 색을 하나 더 보탠다 | 손대지 않는다. 검사기 스캔에서 제외하고 별건 이슈로 |
| **범례 색** | 도면·차트에서 색이 의미 전달 수단이다 | 셸만 수렴, 본문은 `ggc-design-allow` 등록 |
| **프레임워크 무수정 원칙** | eGovFrame WAR 등 기능 코드를 못 건드리는 곳 | 시각만 수렴, 수렴 불가 부분은 등록 |

## 원격 push 정책

리스킨은 서비스 저장소를 건드린다. **push 가 승인된 저장소만 push 한다** — 목록은 운영 규약 문서(플랫폼)가 정본이다.
나머지는 **로컬 커밋까지**만 한다.
