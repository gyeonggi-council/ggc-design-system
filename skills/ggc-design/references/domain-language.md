# 업무 어휘 — 색이 맞는데도 "의회사무처 업무 같지 않은" 이유

> 사용자 지적(2026-08-22): **"지금은 전혀 경기도의회사무처 업무라는 느낌이 없어."**
>
> 이 말이 나온 시점에 토큰 정본은 이미 통과였고, 그 말을 들은 서비스들은 `G-DESIGN` 을
> 통과한 축이었다. **색·셸·파비콘이 다 맞아도 이 지적은 남는다** — 검사기가 재는 것과
> 사람이 "업무 화면"으로 알아보는 것이 다른 층이기 때문이다.

`check_design.py` 는 **값**을 잰다(팔레트·폰트·대비·셸 존재). 이 문서는 **어휘와 밀도**를
다룬다. 자동 판정이 어려운 층이라 규칙이 아니라 **판정 목록과 처방**으로 둔다.

## 무엇이 어긋나는가 — 다섯 가지

### 1. 상태 어휘가 제품 어휘다

공공 업무 화면의 상태는 **결재·문서 흐름에서 온다.** 앱 상태를 그대로 노출하면
"업무"가 아니라 "도구"로 읽힌다.

| 쓰지 말 것 | 쓸 것 |
|---|---|
| 진행중 / 완료 / 실패 | **접수 · 검토 · 결재 · 시행 · 완료 · 반려** |
| Active / Pending / Done | 한글. 영문 상태 라벨을 화면에 남기지 않는다 |
| 삭제 | **반려 · 회수 · 취소** (되돌릴 수 있는지가 어휘로 드러나야 한다) |
| 사용자 / 유저 | **담당자 · 신청인 · 심사위원 · 의원 · 소관부서** |

각 서비스의 실제 절차를 `service-spec.md` 에서 가져온다. **일반 명사로 바꾸지 않는다** —
표창은 "추천 → 접수 → 심사 → 확정 → 수여", 의안은 "발의 → 회부 → 심사 → 의결" 이고,
이 순서 자체가 사용자가 아는 업무다.

### 2. 첫 화면이 목록이 아니다

공공 업무 시스템에서 사람이 처음 보고 싶은 것은 **"내가 처리할 건이 몇 건인가"** 다.
히어로 · 큰 카드 그리드 · 환영 문구로 시작하면 소비자 앱처럼 읽힌다.

- **기본은 표다.** 카드는 건수가 적고 시각 정보가 본질일 때만(예: 회의 영상).
- 표에는 **식별자·소관·기간·담당·상태**가 있어야 한다. 접수번호·문서번호가 있으면 **왼쪽 첫 열**이다.
- **건수를 숫자로 보여 준다.** "처리할 건 3" 이 "환영합니다" 보다 업무적이다.
- 정렬 기본값은 **최근 접수순**이고, 필터 기본값은 **내 소관 · 처리 대기**다.

### 3. 밀도가 낮다

여백이 많고 글자가 큰 화면은 세련돼 보이지만, **한 화면에서 20건을 훑어야 하는 업무**에는
맞지 않는다. 담당자는 스크롤보다 대조를 한다.

- 표 행 높이를 넉넉하게 잡지 않는다. 한 화면에 **15~20행**이 들어와야 한다
- 한 건의 요약에 **줄바꿈을 쓰지 않는다** — 한 행에 담기게 열을 설계한다
- 일러스트·큰 아이콘·이모지를 상태 표시에 쓰지 않는다. 배지와 텍스트로 충분하다
- 숫자는 **오른쪽 정렬 + 천단위 구분**, 날짜는 **`YYYY-MM-DD`** 로 고정한다

### 4. 기관 맥락이 화면에 없다

- 상단에 **기관명**(경기도의회사무처)과 **소관 조직**(의정국·총무과 …)이 보인다
- 회기·차수를 다루는 서비스는 **제N대 · 제NNN회 · 제N차** 표기를 그대로 쓴다
- 근거 조문이 있는 업무는 **조례·규칙명을 화면에 적는다**(예: 표창 심사 기준)
- **인쇄를 가정한다.** 공문·명단·심사표는 출력된다. `@media print` 로 내비게이션을
  걷어내고 제목·기관명·출력일시를 남긴다. 이것 하나가 "업무 시스템" 인상을 크게 바꾼다

### 5. 문장이 마케팅 카피다

앞 넷이 **무엇을 보여 주는가**의 문제라면 이것은 **어떻게 쓰는가**의 문제다. 표와 배지가
다 맞아도 문장 한 줄이 제품 소개서처럼 읽히면 업무 화면이 아니게 된다.

- **평서형 종결(–다)이 기본이다.** "…한다", "…이다", "…하지 않는다". 존댓말(–습니다)은
  **사용자에게 직접 말을 거는 자리**에만 쓴다 — 빈 상태·오류 문구가 그것이다.
  "처리할 항목이 없습니다", "조건에 맞는 의안이 없습니다".
- **주어는 사람이 아니라 문서·의안이다.** "귀하의 문서" 같은 2인칭 소유를 쓰지 않는다.
  예외는 Monitor 첫 화면 인사말 하나 — `{이름}님, 오늘 처리할 {업무} {N}건이 있습니다`.
- **호칭은 실명·역할·부서.** "정책지원관 이○○ · 기획재정위원회". 공개 화면의 사람 이름은
  `이○○` 로 마스킹하고, **UUID 를 사용자에게 보여주지 않는다**(계약 §2).
- **라벨은 명사구.** "저장하기"보다 **"임시저장"**, "의안 등록", "계속심사", "처리율".
  액션에는 방향 기호를 붙인다 — `＋ 의안 등록`, `← 이전`, `다음 →`.
- **숫자는 항상 단위와 함께.** "147건", "80.3%", "경과 161일", "1,284,000(백만원)".
  천단위 콤마와 `tabular-nums` 는 예외가 없다.
- **상대시간을 쓰지 않는다.** "3시간 전"이 아니라 `2026-08-18` 또는 `08-25 (월) 10:00`.
  회기 업무는 **절대 시각이 근거**다 — 언제 열람했느냐에 따라 값이 달라지면 증적이 안 된다.
- **법령 인용은 낫표.** 「청년기본법 시행령」 제6조 제2항. 조례명은 **공포된 명칭 그대로** 쓴다.
- **오류 문구는 사유와 근거를 함께 준다.** "입력값이 잘못되었습니다"가 아니라
  "상위법이 정한 상한(25명)을 초과한다 — 「청년기본법 시행령」 제6조 제2항".
- **AI 산출물에는 근거를 병기한다.** 출처 없이 결과만 보여주지 않는다.
- **상태 기호는 유니코드로.** ● 회기 중 · ◆ 회의일 · ○ 비회기 · ✓ 승인 · ◷ 대기 · ✕ 반려 ·
  ▲▼ 추이 · § 조문 · ⚠ 경고. **기호는 배지·버튼 안에서 항상 텍스트와 함께** 나온다.
  이모지는 UI 문구에 쓰지 않는다.
- **자기 서비스를 자랑하지 않는다.** "혁신적인", "손쉽게" 류의 형용사가 정본에 0건이다.

> 아이콘 자산은 정본에 **없다.** 예제 갤러리의 📋 ✓ ◷ ✕ 📄 🗓 은 자산이 없어 임시로
> 채운 자리이지 브랜드 어휘가 아니다. 아이콘이 필요하면 인라인 스트로크 SVG
> (`viewBox="0 0 24 24"` · `fill="none"` · `stroke="currentColor"` · `stroke-width` 2 ·
> 15~17px 렌더 · `aria-hidden="true"` + 버튼의 `aria-label`)로 그리고, 색은
> `--ggc-text-muted`(액션) 또는 `--ggc-text-faint`(장식)를 쓴다. **CDN 세트를 링크하지
> 않는다** — 검사기 D4 가 잡고 망분리에서 깨진다.

## 대민 화면은 어휘가 뒤집힌다 (v2.0)

위 다섯은 **업무 화면**의 어휘다. 도민이 보는 대민 화면(`data-ggc-profile="public"`)은 방향이 다르다 —
같은 조직이 만들지만 읽는 사람이 다르다.

| 축 | 업무 | 대민 |
|---|---|---|
| 종결 | 평서형(–다) | **존댓말(–합니다)** 전면 |
| 상태 어휘 | 결재 단계 그대로(회부 · 상신) | 같은 단계를 쓰되 **풀이 한 줄** ("회부 — 위원회에 심사를 맡기는 것") |
| 첫 화면 | 목록 · 건수 | **안내 + 검색 + 바로가기** — 무엇을 할 수 있는지가 먼저 |
| 밀도 | 15~20행 | 8~12행. 컨트롤 48px, 본문 17px (프로필이 자동으로 준다) |
| 사람 | 실명 · 역할 · 부서 | 의원은 `○○○ 의원`, 직원 실명은 **담당 연락처에만** |
| 기관 맥락 | 소관 조직 | **담당 부서 + 대표전화 + 운영시간** — 없는 안내 페이지는 완성이 아니다 |
| 개인정보 | — | 수집 항목 · 목적 · 보관 기간 · 미동의 시 불이익을 **서식 안에** (「개인정보 보호법」 제15조) |
| 오류 문구 | 사유 + 근거 조문 | 사유 + **다음에 할 일** ("20자 이상 적어 주세요 — 현재 0자") |
| 인쇄 | 명단 · 심사표 | 안내문 · 신청서 |

지키는 것은 같다 — 날짜 `YYYY-MM-DD`, 상대시간 금지, 「낫표」 법령 인용, 이모지 금지, 자랑 형용사 0건.

## 판정 목록 — 화면마다 물어본다

Phase 1 의 6문항과 함께 확인한다. **아니오가 셋을 넘으면 색이 맞아도 업무 화면이 아니다.**

- [ ] 상태 라벨이 **그 업무의 결재·처리 단계** 어휘인가 (제품 어휘가 아닌가)
- [ ] 첫 화면이 **목록**이고, 기본 필터가 **내 소관 · 처리 대기**인가
- [ ] 표에 **식별자·소관·기간·담당·상태** 열이 있는가
- [ ] 한 화면에 **15행 이상**이 들어오는가
- [ ] 날짜가 `YYYY-MM-DD`, 숫자가 오른쪽 정렬·천단위 구분인가
- [ ] 화면 어디에도 **영문 UI 라벨·이모지 상태 표시**가 없는가
- [ ] 상단에 **기관명과 소관 조직**이 있는가
- [ ] 근거 조례·규칙이 있는 업무면 **그 이름이 화면에 있는가**
- [ ] 출력이 필요한 화면에 **`@media print`** 가 있는가
- [ ] 문장이 **평서형(–다)** 인가 (존댓말은 빈 상태·오류 문구에만 있는가)
- [ ] **상대시간("3시간 전")이 0건**인가 — 회기 업무는 절대 시각이 근거다
- [ ] 법령·조례를 **「낫표」+ 공포 명칭 그대로** 인용하는가
- [ ] 오류 문구가 **사유와 근거**를 함께 주는가
- [ ] AI 산출물에 **출처가 병기**되는가
- [ ] "혁신적인"·"손쉽게" 류 **자랑 형용사가 0건**인가
- [ ] 빈 상태 문구가 **다음 행동**을 말하는가 ("데이터가 없습니다"가 아니라 "접수된 건이 없습니다. 추천서 등록으로 시작합니다")

## 하지 말 것

- **"공공기관스럽게" 를 촌스럽게로 오해하지 않는다.** 밀도와 어휘의 문제이지
  1990년대 표 테두리를 되살리는 일이 아니다. 토큰·컴포넌트는 그대로 쓴다.
- **어휘를 일괄 치환하지 않는다.** DB 값·API 열거형까지 한글로 바꾸면 이관·연계가 깨진다.
  **표시층에서만** 바꾸고 매핑표를 코드 한 곳에 둔다.
- **새 색을 만들지 않는다.** 상태 어휘가 늘었다고 상태색을 발명하지 않는다 —
  정본의 배지 변형으로 표현하고, 모자라면 **정본을 먼저 고친다.**
- **이 문서를 검사기로 만들지 않는다.** 어휘 적합성은 기계가 판정할 수 없고,
  억지로 자동화하면 통과를 위한 문구가 생긴다. **사람이 화면을 보고 판정한다.**

## `G-DESIGN` 과의 관계

이 판정 목록은 **`G-DESIGN` 의 통과 조건이 아니다.** 게이트는 재현 가능한 것만 담는다
(그렇지 않으면 산문 증거가 되살아난다 — `gate_sweep.py` 가 잡는 바로 그 문제다).

대신 **`state.json.design.domain_review`** 에 판정 결과와 미충족 항목을 남긴다.
사용자에게 화면을 보일 때 이 목록을 함께 제시하면, "느낌이 없다"는 지적이
**어느 항목인지 특정된 지적**으로 바뀐다. 그것이 이 문서의 목적이다.
