# 공통 디자인 스킬

**디자인 드리프트는 되돌리기가 가장 비싼 종류의 부채다.** 코드는 리팩터링하면 되지만 색은
전 화면·전 스크린샷·전 인수 증적을 함께 바꿔야 한다. 지금 주 색상이 **9종**인 것은 각 시점에
"이번만" 이 아홉 번 쌓인 결과다. **이 스킬의 목적은 열 번째를 막는 것이다.**

정본은 이미 두껍다 — 토큰 CSS · 컴포넌트 CSS · 계약 문서 · 505줄 실측 문서 · `.dc.html` 원본 8개.
**부족했던 것은 디자인이 아니라 강제력이다.** 그래서 이 스킬의 첫 명령은 문서가 아니라 검사기다.

**이 스킬을 쓰는 두 상황**

| 상황 | 진입 | 출구 |
|---|---|---|
| **신규 배포 중** (`/1ggc-deploy` Phase 2.5) | `state.json.phase` 가 `scaffolded` 이상 | `G-DESIGN` 통과 → `phase: design-ready` |
| **가동 중 서비스 리스킨** | 현재 팔레트·스크린샷을 **기준선으로 먼저 고정** | `G-DESIGN` 통과 + 시각 회귀 전후 비교 |

`design-ready` 는 `../ggc-deploy/SKILL.md` 의 `phase` enum 에 **이미 있는데 아무도 세우지 않던
상태**다. 이 스킬이 그 자리를 채운다 — 새 상태를 발명하지 않는다.

## 관통 원칙 — 이름은 복제해도 되고, 값은 복제하면 안 된다

이 조직에서 값 복제는 **이미 실패한 실험**이다. 계약 문서가 선언한 `#0A7B4E` 는 2026-08-22
까지 문서 세 곳에만 있었고 서비스 채택은 0이었다. 문서 v1.2 와 파일 v1.1 이 세 곳에서
어긋나 있던 것도 같은 기제다(2026-08-22 해소).

- **토큰 이름**(`--ggc-primary`)은 소비자와의 인터페이스다 → references 가 색인해도 안전
- **값**(`#3c5d93`)은 구현이다 → **정본 CSS 한 곳에만** 산다.
  이 스킬의 references 가 값을 적는 순간 그 줄은 낡기 시작한다

값을 봐야 하면 정본 파일을 연다. 예외는 `references/contract.md` 의 **승격 대기표** 하나뿐이며,
그것은 팔레트가 아니라 작업 목록이다.

## Phase 1 — 결정 대화 (6문항)

디자인은 갈릴 축이 인증보다 적다. **6개만 묻고 기본값이 명백한 것은 건너뛴다.**

1. **셸 형태** — ⓐ 유틸리티바만(단폭 PoC) / ⓑ 계약 풀셸(GNB 64 + LNB 256) / ⓒ 이관 셸 유지 + 유틸리티바
   > 기본값 ⓐ. **화면이 5개를 넘으면 ⓑ 를 권한다** — LNB 없이 5화면을 넘기면 반드시
   > 자체 내비게이션을 발명하게 되고, 그게 다음 드리프트다.
2. **화면별 Archetype** — 각 화면을 6종 중 하나로 판정한다(`references/archetypes.md` 의 판정
   조건표로 고른다). **"둘 다" 는 없다** — 섞으면 처방이 성립하지 않는다.
3. **컴포넌트 레이어** — `ggc-components.css` 를 복사할 것인가. 도입하면 바이트 동일 복사.
4. **AA 모드** — `observe`(기준선을 늘리지 않는다) / `enforce`(4.5:1 전량 강제)
   > 토큰 v1.2 자체는 이미 AA 를 통과한다. 이 스위치는 **서비스 자체 CSS** 에 적용된다.
5. **확폭(≥1680px)** — 채택하면 스크린샷에 1920×1080 이 추가된다(계약 §8-5). 기본값 미채택.
6. **예외 신청** — 브랜드색을 벗어나야 하는 자리가 있는가. 있으면 사유와 함께 등록(Phase 3).

정한 것은 `<서비스명>/docs/service-spec.md` 의 디자인 절과 `state.json` 에 적는다.

> **6문항을 다 정해도 "의회사무처 업무 같지 않다"는 지적은 남을 수 있다.**
> 그 층은 색이 아니라 **어휘와 밀도**다 — 상태 라벨이 결재 단계 어휘인가, 첫 화면이
> 목록인가, 한 화면에 15행이 들어오는가. `references/domain-language.md` 의 판정 목록
> 10개를 함께 돌리고 결과를 `state.json.design.domain_review` 에 남긴다.
> **게이트로 만들지 않는다** — 기계가 판정할 수 없는 것을 게이트에 넣으면 산문 증거가
> 되살아난다.

```json
"design": { "kind": "2.사본형", "shell": "utility-only|full|inherited",
            "archetypes": {"/": "Monitor", "/list": "Explore"},
            "components_css": false, "aa_mode": "observe", "wide": false,
            "allow": [] }
```

## Phase 2 — 토큰과 브랜드 자산 착지

```bash
CANON=/d/260712_경기도의회_시스템구축/design
cp "$CANON/ggc-tokens.css" <정적루트>/ggc-tokens.css      # 손으로 옮겨 적지 않는다

# 폰트도 정본에서 온다(2026-08-25 신설). **두 파일을 같은 폴더에 나란히** 두고
# ggc-tokens.css 보다 **먼저** 링크한다 — 토큰이 그 서체 이름을 쓰기 때문이다.
cp "$CANON/ggc-fonts.css"                          <폰트폴더>/
cp "$CANON/fonts/PretendardGOVVariable.subset.woff2" <폰트폴더>/
```

**⛔ 다른 서비스에서 `PretendardGOV-*.subset.woff2` 를 복사해 오지 말 것.** 그것은 정적 3벌이고
`font-weight: 700 800` 을 Bold 한 파일에 묶는다 — **정본이 제목·KPI 에 22곳에서 요구하는 800 이
700 과 똑같이 그려진다.** 2026-08-25 까지 열 개 서비스가 전부 그 상태였다. 정본은 가변 한 벌
(45~930, 617KB)이며 `url()` 이 상대경로라 basePath 를 CSS 가 알 필요가 없다.

- **바이트 동일이어야 D1 이 성립한다.** 값을 바꿔야 하면 **정본을 먼저 고친다.**
- **자기 스타일보다 먼저 로드한다.** 순서가 곧 우선순위다(D3 가 역전을 잡는다).
- **새 색을 만들지 않는다.** 주 색상이 9종이 된 것이 그렇게 됐다.
- **❸ 인라인형이 핵심 케이스다.** 값이 이미 맞으므로 **값을 건드리지 말고 파일만 도입**하고,
  자기 CSS 의 하드코딩 hex 를 `var(--ggc-*)` 로 **치환만** 한다. 렌더 결과가 같아 회귀가 0이다.
- **❹ 독자형은 역방향 매핑표를 먼저 만들어 사용자에게 보인 뒤** 치환한다.
  표 없이 일괄 `sed` 하지 않는다.

브랜드 자산(파비콘·마크)은 `references/brand-assets.md` 가 정본이다. 복사원은
`design/brand/dist/` 하나뿐이고, 대상 경로는 `design/brand/ASSET-MAP.tsv` 가 고정한다.

## Phase 3 — 공통 셸과 컴포넌트

계약 3종(`.ggc-utility-bar` · `.ggc-badge` · `.ggc-footer`)은 **토큰 파일에 들어 있다** —
복사하면 따라온다. GNB/LNB 풀셸과 반응형은 `ggc-components.css` v1.1 에 있다.
스택별 삽입 지점은 `references/porting.md`.

예외가 필요하면 **코드 옆에서 사유와 함께** 등록한다. eslint-disable 과 같은 형태다.

```css
/* ggc-design-allow: #13778e — 표창관리 이관 브랜드. XL-2026xxxx 리스킨 대기 */
```

① 예외가 위반 옆에 있어 발견되고 ② 사유 없는 예외가 불가능하며 ③ 검사기가 "발명한 색" 과
"승인된 예외" 를 구분한다. 집계는 `state.json.design.allow[]` 로 올려 **총량이 보이게** 한다.
보이지 않는 예외가 드리프트다.

## Phase 4 — 화면 조립

`references/archetypes.md` 의 처방을 순서대로 따른다.

> **먼저 `design\examples\` 를 브라우저로 열어 본다.** `dashboard.html`(Monitor)과
> `wizard.html`(Configure)이 archetype 을 실물 화면으로 조립한 것이고,
> `components.html` 은 각 예제 아래에 **렌더된 그 DOM** 을 그대로 펼쳐 준다.
> 마크업을 짐작해 짜지 말고 거기서 가져온다 — 문서보다 빠르고, 갈라질 자리가 없다.

이 단계의 규칙 넷:

- **빈 상태 · 오류 · 로딩 3종을 함께 만든다.** PoC 에서 가장 자주 빠지고, 시연 당일에 드러난다.
  전용 클래스는 정본에 **없다**(화면마다 문구와 다음 행동이 다르다). 기존 요소로 조립하며,
  조립 예시는 `design\examples\components.html` 마지막 절에 있다.
- **정본에 없는 것을 정본이라 하지 않는다.** 원본 8파일 합계로 `@media` 0 · `aria-*` 0 ·
  `role` 0 · `tabindex` 0 · `focus-visible` 0 이고 `$preview` 는 전부 1440 이다.
  반응형·접근성은 **구현 단계의 신규 결정**이다. 근거는 정본이 아니라 계약 §2·§3 이다.
- **`outline:none` 28건을 복제하지 않는다.** 토큰 v1.2 의 `:focus-visible` 규칙을 쓴다.
- **로그인 화면을 새로 그리지 않는다.** 10개 서비스가 같은 입구를 노출하므로
  `.ggc-qr`(정본 §11)을 그대로 쓴다. 2026-08-22 이전에는 이 컴포넌트가 없어서
  10벌이 각자 발명했고 시각 언어가 셋으로 갈렸다 — 색만 맞추는 수렴으로는
  다음에 또 갈라진다.
- **`style-hover` 는 CSS 가 아니다.** `.dc.html` 에 105건 있는 Claude Design 런타임 전용
  속성이라 자동 변환되지 않는다. 손으로 `:hover` 규칙이 된다(`references/porting.md`).

## Phase 5 — 검증 → `G-DESIGN`

```bash
python /d/260712_경기도의회_시스템구축/design/check_design.py --gate --aa=observe \
       /d/2026-ggc-vibe/ggc-services/<서비스명>
```

증거 3종을 `state.json.gates["G-DESIGN"]` 에 기록하고 `phase` 를 `design-ready` 로 전진시킨다 —
**검사기 출력 전문** + **1440×900 / 390×844 스크린샷**(확폭 채택 시 1920×1080 추가) +
**브라우저 콘솔 0건**. 자세한 절차와 실패 시 복귀 지점은 `references/verify.md`.
